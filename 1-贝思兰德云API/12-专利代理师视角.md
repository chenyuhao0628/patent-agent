## 二、我的案件

`GetPersonalCase` 返回的是**当前登录人承办的案件**，行内 `CaseProcUndertakerUserName` 即承办人。

```bash
curl -sS -k -X POST "$API/CaseInfo/GetPersonalCase" \\
  -H "Authorization: $TOKEN" -H 'Origin: $ORIGIN' \\
  -H 'Language: zh-CN' -H 'Content-Type: application/json' \\
  -d '{"PagedInfo":{"pageIndex":1,"pageSize":100},"ProcStatusTypeList":[0],
       "TableType":50010,"ActiveName":"waitHand","SelectedProcIdGroup":[]}' \\
| python3 -c '
import json,sys
for r in json.load(sys.stdin)["Data"]:
    n=r.get("CaseProcNameInfo") or {}
    print("%-14s %-8s %-22s %-28s 法定=%s 自定义=%s" % (
        r.get("CaseNo"), n.get("ProcCode"), n.get("CaseProcName"),
        (r.get("CaseName") or "")[:26],
        str(r.get("CaseProcLegalDate"))[:10], str(r.get("CaseProcCustomDate"))[:10]))
'
```

五个页签的 `TableType`：

| TableType | `ActiveName` | `ProcStatusTypeList` | 含义 |
| --- | --- | --- | --- |
| 50010 | `waitHand` | `[0]` | 待办 |
| 50011 | `auditing` | `[200]` | 待审核 |
| 50012 | `waitDeliver` | `[300]` | 待递交 |
| 50013 | `delivering` | `[400]` | 递交中 |
| 50014 | `finish` | `[500]` | 已完成 |

## 三、我的撰写任务（审核稿流程）

**这是代理师最核心的工作流，此前完全没有文档。**

审核稿 = 撰写稿。一条审核稿有自己的生命周期，与案件流程并行。

### 3.1 七个计数

```bash
curl -sS -k --get "$API/CaseInfo/GetCaseReviewDraftInfoCount" \\
  -H "Authorization: $TOKEN" -H 'Language: zh-CN'
```

返回：

```json
{
  "PendingCount": 0,        "MyPendingCount": 0,
  "WorkAgentCount": 0,      "ProcessingCount": 0,
  "StartCount": 0,          "FinishCount": 0,
  "EntrustCaseCount": 0
}
```

| 字段 | 推测含义 |
| --- | --- |
| `StartCount` | 待开始 |
| `ProcessingCount` | 处理中 |
| `PendingCount` | 待处理（他人待我审核？） |
| `MyPendingCount` | **我的待处理** |
| `WorkAgentCount` | **承办撰写的数量** |
| `FinishCount` | 已完成 |
| `EntrustCaseCount` | 委托案件 |

> ⚠️ **上表的含义是推测**（字段名直译 + 与四阶段 List 接口对应），**尚未实机确认**。本账号全部为 `0`，无数据可验证。

### 3.2 四阶段列表

```text
POST /CaseInfo/GetCaseReviewDraftInfoOfStartList        待开始
POST /CaseInfo/GetCaseReviewDraftInfoOfProcessingList   处理中
POST /CaseInfo/GetCaseReviewDraftInfoOfPendingList      待处理
POST /CaseInfo/GetCaseReviewDraftInfoOfFinishList       已完成
```

配套 Count 接口同名（`...OfStartCount` 等），请求体传 `{}` 即可。

#### 请求体：用 `PageInfo`，不是 `PagedInfo`

```bash
curl -sS -k -X POST "$API/CaseInfo/GetCaseReviewDraftInfoOfStartList" \
  -H "Authorization: $TOKEN" -H 'Origin: $ORIGIN' \
  -H 'Language: zh-CN' -H 'Content-Type: application/json' \
  -d '{"PageInfo":{"pageIndex":1,"pageSize":20,"SortField":null,"SortType":null}}'
```

| 字段 | 说明 |
| --- | --- |
| `PageInfo` | **必需**，含 `pageIndex` / `pageSize` / `SortField` / `SortType` |
| `IsWorkAgent` | 可选，工作组视图 |
| `UserTableTitleColumnList` | 可选，指定返回列 |

> ⚠️ **字段名是 `PageInfo`，不是 `PagedInfo`**——用错会报 `系统错误: e`。这与 `/ajlist/*` 的 `page`/`size`、工作台的 `PagedInfo` 都不同，三种写法并存。

#### 行内字段

从字段名与表格列定义整理，**行内可能包含**：

| 字段 | 含义 |
| --- | --- |
| `CaseReviewDraftId` | 审核稿 ID |
| `CaseProcReviewDraftUserName` | **撰写人** |
| `CaseProcStartReviewDraftDate` | 开始撰写日期 |
| `CaseProcReviewDraftSubmitDate` | 提交日期 |
| `CaseProcReviewDraftBackDate` | 退回日期 |
| `CaseProcReviewDraftBackCount` | **退回次数** |
| `CaseProcNewReviewDraftUserName` / `CaseProcOldReviewDraftUserName` | 转办前 / 后撰写人 |
| `CaseReviewDraftStepId` | 当前节点 ID |
| `CaseReviewDraftRelationProcId` | 关联的流程 ID |
| `CanStartReviewDraft` | 是否可开始撰写 |
| `ExistsReviewDraft` / `ExistsReviewDraftOrHand` | 是否存在审核稿 / 审核稿或递交 |

### 3.3 审核稿的流程操作

```text
GET  /CaseInfo/IsExistsReviewDraft?caseProcId=        该案有无审核稿
GET  /CaseInfo/StartReviewDraft                       开始撰写
POST /CaseInfo/SaveReviewDraftFlow                    保存
POST /CaseInfo/SubmitReviewDraftFlow                  提交
POST /CaseInfo/SubmitReviewDraftTurnHandlerFlow       转办
POST /CaseInfo/BackReviewDraftFlow                    退回
GET  /CaseInfo/CancelCaseReviewDraft                  取消
GET  /CaseInfo/ReStartReviewDraft                     重新开始
GET  /CaseInfo/CreateReviewDraftHurryNotice           催办
GET  /CaseInfo/GetReviewDraftCurrentFlowInfo          当前节点
GET  /CaseInfo/GetReviewDraftNextFlowInfo             下一节点
GET  /CaseInfo/GetReviewDraftBackList                 退回记录
GET  /CaseInfo/GetReviewDraftHistoryList              历史
GET  /CaseInfo/GetReviewDraftDeadlineTypeInfo         期限类型
```

### 3.4 审核稿的文件与费用

```text
POST /CaseInfo/UploadReviewDraftFile                  上传稿件
GET  /CaseInfo/GetReviewDraftFileList                 稿件文件列表
POST /CaseInfo/GetReviewDraftFileListByCaseProcId     按流程取稿件
GET  /CaseInfo/DeleteReviewDraftFile                  删除
GET  /CaseInfo/GetReviewDraftPayList                  稿费列表
GET  /CaseInfo/GetReviewDraftPayDetail                稿费明细
GET  /CaseInfo/GetReviewDraftPayScoreInfo             稿费积分  ← 代理师计酬
GET  /CaseInfo/GetReviewDraftRulePayInfo              计酬规则
```

**`GetReviewDraftPayScoreInfo` 是代理师绩效相关的接口**，实测可调用（本账号无数据）。

#### 稿费/点数的计算因子

从计酬明细表的列定义可以看出，点数按规则计算，影响因素有：

| 字段 | 名称 |
| --- | --- |
| `CaseLevelName` | 案件等级 |
| `TenantUserLevelName` | 人员级别 |
| `NumberResponsesType` | 答辩/补正次数 |
| `IsPriorty` | 是否主张优先权 |
| `IsSubmitApplyHandler` | 是否为提出申请处理人 |
| `UserType` | 人员类型 |
| `IsEntrustThirdpartyAgency` | 是否委托第三方代理机构 |
| `IsAcceleratedReview` | 是否加快审查 |
| `RuleDateTypeName` | 规则日期类型 |
| `CountryName` / `ApplyTypeName` | 国家 / 申请类型 |

结果字段：

| 字段 | 含义 |
| --- | --- |
| `PayValue` | **点数** |
| `AuthPayValue` | 授权点数 |
| `ReviewDrafterPayValue` | **撰写人点数** |
| `PayValueRemark` | 备注 |
| `WriteUnitPrice` / `ReviewDraftUnitPrice` / `AuthorizeUnitPrice` | **撰写 / 审核 / 授权单价** |
| `CommissionOrderPtReviewDraftUserCommissionAmount` | 提成金额 |

**即：代理师的稿费＝按案件等级、人员级别、答复次数、是否加急等因子乘上单价算出的点数。**

## 四、撰写质量规则（`IReviewDraftRule`）

系统内置的三类词库，用于稿件质量检查：

```text
POST /IReviewDraftRule/GetDisabledWordList        禁用词
POST /IReviewDraftRule/GetSensitiveWordList       敏感词
GET  /IReviewDraftRule/GetSplitWordById           拆分词
```

三个 List 与 Count 接口**实测全部有权限**（本账号各 0 条，即未配置词库）。

### 智能审核（`IReviewDraft`）

```text
POST /IReviewDraft/GetReviewDraftLogList        审核日志
POST /IReviewDraft/GetReviewDraftLogListCount   审核日志计数

POST /IReviewDraft/ReviewDraft                  审稿
GET  /IReviewDraft/ReviewDraftBySingleDoc      单文档审稿
```

**权限全部可用。**

## 八、代理师日常最实用的四个查询

```text
① 我的待办        GetPersonalCase(waitHand)          ← 手上有哪些案子
② 我的撰写任务    GetCaseReviewDraftInfoCount         ← 四阶段计数
③ 我的答复期限    CPC 客户端 /yjcs/dfsc/wtj/list      ← 官方口径，含顺延
④ 我的递交状态    GetPersonalCase(delivering) +
                  GetHandInfo.IsPackageSendSuccess    ← 是否已递交官方
```

**注意**：`CaseInfo` 下的法定/自定义期限**不可靠**（无工作日顺延），答复类期限一律以 CPC 客户端的 `yuqirq` 为准，见 [4-只读-流程链路与卡点.md](./4-只读-流程链路与卡点.md) 2.5.1。
