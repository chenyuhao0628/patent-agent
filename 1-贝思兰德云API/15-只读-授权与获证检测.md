**本页解决：一个案子有没有授权、有没有获证，从哪一条接口能看出来；案卷里的授权字段什么时候才有值。**

> **范围**：只覆盖中国专利（`ItemTypeName` 带「(中国)」的类目）。无效、商标、涉外线不在本页。

---

## 一、结论先说

| 问题 | 结论 |
| --- | --- |
| 能查到「已授权」吗 | **能**。`/NoPermissionRequired/GetCaseNewTrends*` 的 `ItemType=2 授权专利(中国)`，明细行带案号、客户、`PostDate` |
| 能查到「已获证」吗 | **能**，同一接口 `ItemType=8 获证专利(中国)`。**两者不是同一时点**：实测同一案 2026-09-14 是「授权 1 条、获证 0 条」 |
| 案卷字段里有授权信息吗 | 有——`GetUpdateCaseInfo` 的 `CaseInfo.AuthorizeDate` / `AuthorizePostDate` / `CertificateDate` / `CertificateNo` / `IssueDate` / `IssueNo`；**但实测连「专利证书已下发」的案件这些字段仍全为空**（见第四节），**不要用它判断授权** |
| 案件列表行里能看吗 | **不能**。`GetPersonalCase` 各页签行里这些同名字段恒为 `null`（三个页签抽样验过） |
| 「案件状态」能代替吗 | **不能**。`CaseStatusId` 是**所内自定义状态**，与官方授权不同步（实测该案仍为「一通回案实审」） |
| 有官文可以佐证吗 | 有，而且**能直接下载**：动态明细行的 `NoticeId` → `GetNoticeById` → `FileList[].FileNo` → 文件下载（实测 PDF 校验通过）。授权类官文的名字是**「办理登记手续通知书」**（`NoticeTypeCode=200602`） |
| 官文到了就算进案卷了吗 | **不算**。实测该案办登通知书 `NoticeStatus=200 待导入`——已在官文库、尚未导入案卷，案件文件中心与案件流程里都还没有 |

**一句话**：判断「是否授权」看**案件新动态**；**案卷字段是所内登记，可能滞后于官方**。

## 二、首选：案件新动态

前缀 `/NoPermissionRequired/`，免权限、只读，本账号实测可用。

### 2.1 一次请求看全部类目（最省的巡检信号）

```bash
curl -sS -k "$API/NoPermissionRequired/GetCaseNewTrendsStatisticsCount" \
  -H "Authorization: $TOKEN" -H 'Language: zh-CN'
```

返回 `Data`（**节选**，实测本账号返回订阅的 11 类）：

```json
{
  "ReminderDuration": 7,
  "ItemList": [
    {"ItemType": 1, "ItemTypeName": "受理专利(中国)", "Count": 0},
    {"ItemType": 2, "ItemTypeName": "授权专利(中国)", "Count": 1},
    {"ItemType": 8, "ItemTypeName": "获证专利(中国)", "Count": 0}
  ]
}
```

只返回**订阅的类目**（见 2.4），不是 13 类全给。比对 `ItemType=2/8` 的 `Count` 即可知道「有没有新的授权/获证」。

### 2.2 拿到具体案件（明细）

```bash
curl -sS -k -X POST "$API/NoPermissionRequired/GetCaseNewTrendsDetailList" \
  -H "Authorization: $TOKEN" -H 'Language: zh-CN' -H 'Content-Type: application/json' \
  -d '{"PagedInfo":{"PageIndex":1,"PageSize":50},"ItemType":2,"ReminderDuration":7}'
```

返回行字段（实测）：

```text
NoticeId           官文 ID（可直接查官文详情并下载，见第三节）
CaseId / CaseNo / CaseName / CaseRelationTypeName / ApplyTypeName
PostDate           该动态的发布日期（授权类即授权公告日）
ApplicationNo / ApplicationDate / ApplicantName / InventorName / ClientName
```

只要条数时用 `/NoPermissionRequired/GetCaseNewTrendsDetailCount`，请求体给 `ItemType` + `ReminderDuration` 即可（实测本页样例返回 `Data=1`）。

### 2.3 `ItemType` 全集（13 类）

取自 `GET /SystemTypeSetting/GetCaseNewTrendsItemTypeDropDown`：

| 值 | 含义 | 值 | 含义 |
| --- | --- | --- | --- |
| 1 | 受理专利(中国) | 8 | **获证专利(中国)** |
| 2 | **授权专利(中国)** | 9 | 视撤专利(中国) |
| 3 | 审查意见专利(中国) | 10 | 其他官文(中国) |
| 4 | 补正专利(中国) | 11 | 手续合格(著录项目变更) |
| 5 | 驳回专利(中国) | 12 | 手续合格(撤回专利申请) |
| 6 | 法限到期专利 | 13 | 手续合格(放弃专利权) |
| 7 | 审查业务专用函专利(中国) | | |

**本页只用 2 与 8。**

### 2.4 窗口与订阅口径

```bash
curl -sS -k "$API/NoPermissionRequired/GetCaseNewTrendsUserSetting" \
  -H "Authorization: $TOKEN" -H 'Language: zh-CN'
```

```json
{"ReminderDurationType": 1, "ReminderDuration": 7, "IsStatisticsMyClientsCase": false,
 "ItemTypeList": [1, 2, 3, 4, 5, 6, 7, 8, 11, 12, 13]}
```

- `ReminderDuration`：窗口天数，默认 **7**。统计接口不吃 query 参数（实测 `?ReminderDuration=30` 仍返回 7），窗口以本设置为准；明细接口的 `ReminderDuration` **可以**覆盖，实测 7 与 30 都生效。
- `ItemTypeList`：**用户订阅的类目**——统计接口只回这些。实测该账号订阅 11 类，因此统计里看不到 9 视撤、10 其他官文；**不要把「没返回」当成「系统没有」**。
- `IsStatisticsMyClientsCase`：是否只统计「我的客户」。本账号为 `false`。

### 2.5 期限类变体

`POST /NoPermissionRequired/GetCaseNewTrendsLegalDateDetailCount` 与 `.../GetCaseNewTrendsLegalDateDetailList`，请求体同 2.2。本账号实测 0 条。

### 2.6 参数陷阱

| 现象 | 原因 |
| --- | --- |
| `系统错误: e` | **明细接口的请求体不能是空对象**，必须带 `PagedInfo`（`{"PagedInfo":{"PageIndex":1,"PageSize":20}}` 就正常）；`...DetailCount` 不带 `PagedInfo` 也可（实测给 `ItemType` + `ReminderDuration` 即返回 `Data=1`） |
| 明细拿到一堆别的案子 | 明细是「按类目 + 窗口」，**没有按案号筛的参数**。要按案查：取该类目明细后按 `CaseNo`/`CaseId` 匹配 |
| 统计少了几类 | 订阅设置（2.4 的 `ItemTypeList`），不是接口能力 |
| `IsSuccess=true` 且 `Data=0` | 窗口内该类动态为 0 条，**不是失败**（实测 `GetCaseNewTrendsLegalDateDetailCount` 返回 `Data=0`） |

---

### 2.7 只要「授权 / 驳回」两个结果

**要的就是官方结论、不看文件**时，两类目足矣——`ItemType=2`（授权专利(中国)）与 `ItemType=5`（驳回专利(中国)），**两者都已在当前订阅列表里**，不需要改任何设置：

```bash
# 1 次请求：拿到「授权几条 / 驳回几条」
curl -sS -k "$API/NoPermissionRequired/GetCaseNewTrendsStatisticsCount" \
  -H "Authorization: $TOKEN" -H 'Language: zh-CN'

# 想知道是哪几个案子：按类目取明细（每次只给一个 ItemType）
curl -sS -k -X POST "$API/NoPermissionRequired/GetCaseNewTrendsDetailList" \
  -H "Authorization: $TOKEN" -H 'Language: zh-CN' -H 'Content-Type: application/json' \
  -d '{"PagedInfo":{"PageIndex":1,"PageSize":50},"ItemType":2,"ReminderDuration":7}'
```

**但这只是「近 N 天的新动态提醒」，不是「案件结论查询」**——实测：

| 检验 | 结果 |
| --- | --- |
| 明细传 `ReminderDuration=365`（甚至 36500） | **不生效**。已知 47 天前的「驳回决定」、41 天前的「第一次审查意见通知书」都**没有**出现在动态里；`ItemType=2` 在 7/30/90/365/3650/36500 六个窗口下返回同一个条数 |
| 窗口内的事件 | 都出现（09-10 / 09-14 / 09-15 的动态全部命中） |
| 结论 | 窗口以 `GetCaseNewTrendsUserSetting.ReminderDuration`（默认 7 天）为准，**明细参数改不了它** |

⚠️ **驳回类目暂未验证**：本账号两件有「驳回决定」的案子（对应日期 07-29、08-27）都超出 7 天窗口，`ItemType=5` 在 365 天口径下仍返回 0，**因此「7 天内发生驳回时 `ItemType=5` 是否会亮」没有被证实**。要稳，用 3.4 / 3.7 的**案件官文清单**路线（不受窗口限制）。

**明细的两个静默陷阱**：

- `ItemType` **必须给单个值**；写成 `ItemTypeList:[2,5]` 或不给 → 返回 **0 行且不报错**（容易误判成「没有」）。
- 想同时要「授权 + 驳回」，就调两次（或先看计数接口的 11 类汇总）。

## 三、把授权通知书取到手（已验证）

从「知道授权了」到「手里有官文文件」，三步，全部只读。

### 3.1 从动态明细里取 `NoticeId`

第二节明细行的 `NoticeId` 不是动态自己的编号，而是**官文 ID**，可直接查官文详情。

### 3.2 查官文详情

```bash
curl -sS -k --get "$API/CaseInfo/GetNoticeById" \
  -H "Authorization: $TOKEN" -H 'Language: zh-CN' \
  --data-urlencode "noticeId=$NOTICE_ID"
```

返回 `{Case, Notice, NoticeExtend, FileList, NoticeFeeList, NoticeAnnualLateFeeList}`。实测：

| 组 | 字段 | 实测值 |
| --- | --- | --- |
| `Notice` | `NoticeName` / `NoticeTypeCode` | **办理登记手续通知书** / `200602` |
| | `NoticeNumber` | `10173760295294` |
| | `PostDate` / `DownloadDate` | `2026-09-14` / `2026-09-14T04:13:22` |
| | `NoticeStatus` / `NoticeStatusName` | `200` / **待导入** |
| | `Volume` | `0293` |
| `NoticeExtend` | `FaWenXLH` | `2026091400182230` |
| | `CPCAnJuanBBH` / `CPCAnJuanH` | `109126662668` / `10000566531903` |
| | **`DaFuRQ`** | **`2026-11-16`**（该官文的办理/答复期限） |
| `FileList` | 每项 `FileNo` + `FileName` | 同名 `.pdf` 与 `.zip` 各一份 |
| `NoticeFeeList` | `FeeName` / `FeeAmount` | `年费` / `135.00`（`CNY`） |

> **授权类官文在这里叫「办理登记手续通知书」（`NoticeTypeCode=200602`），不叫「授权通知书」。** 看到 200602 即已进入办登阶段。

### 3.3 下载并校验

`FileNo` 取自 `FileList`，下载方式与 [5-只读-表单与通知书.md](./5-只读-表单与通知书.md) §2.7 一致：

```bash
curl -sS -k --get "$API/NoPermissionRequired/FileStorageGetFile" \
  -H "Authorization: $TOKEN" -H 'Language: zh-CN' \
  --data-urlencode "fileNo=$FILE_NO" \
  --data-urlencode 'forBlob=true' \
  -o '办理登记手续通知书.pdf'
```

实测：`.pdf` 610,152 字节、头 5 字节 `%PDF-`；`.zip` 589,996 字节、头 4 字节 `PK\x03\x04`。**判断类型先看文件头，别只看扩展名。**

### 3.4 另一入口：案件官文清单

不知道 `NoticeId` 时，直接列该案全部官文：

```bash
curl -sS -k -X POST "$API/CaseInfo/GetNoticeListByCaseId" \
  -H "Authorization: $TOKEN" -H 'Language: zh-CN' -H 'Content-Type: application/json' \
  -d "{\"caseId\":\"$CASE_ID\",\"PagedInfo\":{\"PageIndex\":1,\"PageSize\":100}}"
```

实测该案 8 条（`PostDate` 倒序）：办理登记手续通知书(09-14) → 电子申请回执 ×3(09-07 / 09-04 / 09-03) → 第一次审查意见通知书(08-26) → 进入实质审查阶段通知书(07-17) → 公布通知书(07-17) → 初步审查合格通知书(06-30)。

每行带 `NoticeName`、`NoticeTypeCode`、`PostDate`、`NoticeStatusName`、`IsRead`、`IsUserDownloaded`、`FileList`；条数用 `GET /CaseInfo/GetNoticeListByCaseIdCount?caseId=…`（实测 `Data=8`）。

### 3.5 「已下载」不等于「已进案卷」

实测该案办登通知书：`NoticeStatus=200 待导入`、`IsUserDownloaded=false`，而**案件文件中心没有它、案件流程里也没有办登节点**。

官文状态字典（`GET /SystemTypeSetting/GetNoticeStatusType`）：

| 值 | 含义 |
| --- | --- |
| 99 | 无需导入 |
| **200** | **待导入**（已进官文库、未进案卷） |
| 300 | 已导入 |
| 400 | 异常官文 |
| 500 | 未关联案件 |

> 结论：**「授权已到」能看到、附件也下载得到，但案卷侧（文件中心、办登流程）要人工导入才会出现。** 判断案卷口径请用 `GetNoticeListByCaseId` 的 `NoticeStatusName`，不要只看案件文件中心。

### 3.6 全局官文列表在本账号不可用

`POST /CaseInfo/GetNoticeList`、`GET /CaseInfo/GetNoticeListTabCount`、`GET /CaseInfo/GetNoticeListChildTabCount` 实测均返回 `无访问权限`（本账号未开通官文管理模块）。注意 `TabCount` 会返回**全零占位对象**且 `IsSuccess=false`，**不要把它当成「没有官文」**。可用的是案件级 `GetNoticeListByCaseId`。

### 3.7 官文类型码判读表（「只要结果」时就用这张表）

配合 3.4 的案件官文清单使用：**只看 `NoticeName` / `NoticeTypeCode`，不用下载、不用导入**，即可判断官方结论。

类型码取自官方字典 `GET /NoticeType/GetNoticeTypeDropDown`（实测 **337 条**，行字段 `NoticeCode` / `label` / `ApplyTypeCode` / `value`=`NoticeTypeId`；字典本体 `GetNoticeType` 无权限，用 DropDown）。

| 官方结论 | `NoticeTypeCode` | 名称 |
| --- | --- | --- |
| **授权（办登）** | `200602` | 办理登记手续通知书 |
| **获证** | `400001` / `400002` / `400003` | 发明专利证书 / 实用新型专利证书 / 外观设计专利证书 |
| **驳回** | `200305` / `210407` / `210408` | 驳回决定（三个码同名，实测本所两案分别落在 `200305` 与 `210407`） |
| 视为撤回 | `200022` / `201504` | 视为撤回通知书 |
| 视为放弃 | `200007` / `200601` | 视为放弃取得专利申请权或专利权的权利通知书 / 视为放弃取得专利权通知书 |

| 初审 | `210304` | 发明专利申请初步审查合格通知书 |

>
> | 案件 | 官文清单里的官方结果 | 案卷字段 |
> | --- | --- | --- |
> | `202606291-0096`（发明） | 09-14 `200602` 办理登记手续通知书（待导入） | 授权类字段全空 |
> | `202606292-0737` / `-0749`（实用新型） | 08-17 `200602` 办理登记手续通知书 + **09-08 `400002` 实用新型专利证书**（均待导入） | **授权类字段仍全空**，`CaseStatusType=3` 审查中 |
> | `202606292-0880` | 08-27 `200305` 驳回决定 | — |
> | `202606291-0181` | 07-29 `210407` 驳回决定 | — |
>
> **覆盖前提（实测，务必接受）**：官文清单**不是完整历史**。抽查 12 个跨月份案件：**7 个清单为空**（含 6 月立案的 3 件与 8 月新立案的 4 件），各案最早官文分别为 06-29 / 06-30 / 07-08 / 07-28，**12 件全部没有「专利申请受理通知书」(200101)**。因此清单里**没有**某个类型 ≠ 官方没发；用「有 200602 / 40000x / 驳回决定」判定**已有结果**是可靠的，用「没有」判定**没有结果**不可靠。
>
> 想找缺失原因时注意：官文规则接口 `PatentNoticeRule/GetPatentNoticeRuleList`、`GetPatentNoticeRuleItemList` 本账号**无访问权限**，无法从规则侧核对收录范围。

## 四、案卷字段：授权在档案里的落点

```bash
curl -sS -k --get "$API/CaseInfo/GetUpdateCaseInfo" \
  -H "Authorization: $TOKEN" -H 'Language: zh-CN' \
  --data-urlencode "caseId=$CASE_ID"
```

`Data.CaseInfo`（实测 83 个键）中与本页相关的：

| 字段 | 含义 |
| --- | --- |
| `AuthorizeDate` | 授权日 |
| `AuthorizePostDate` | 授权公告日 |
| `CertificateDate` / `CertificateNo` | 证书日 / 证书号 |
| `IssueDate` / `IssueNo` | 公告日 / 公告号 |
| `PublicDate` / `PublicNo` | 公开日 / 公开号 |
| `CaseStatusId` / `CaseStatusType` | 所内案件状态（见第四节） |
| `IsFinishCase` | 是否已结案 |

**实测对照（同一案、同一天）**：

| 来源 | 值 |
| --- | --- |
| 案件新动态 `ItemType=2` | 有 1 条，`PostDate=2026-09-14` |
| `CaseInfo.AuthorizeDate` / `AuthorizePostDate` / `CertificateDate` / `CertificateNo` / `IssueDate` / `IssueNo` | **全部 `null`** |
| `CaseInfo.PublicDate` / `PublicNo` | `2026-07-17` / `CN 122414968 A`（已填） |

**用法**：这两个来源要分角色看——案件新动态 = 官方侧发生了什么；案卷字段 = 所内登记了什么。**授权当天案卷字段通常还是空的**，此时不要据此判断"没授权"，也不要把空值当成接口出错。

**更强的一条实测（2026-09-14）**：`202606292-0737` 与 `-0749` 两件实用新型，官文清单里 `200602 办理登记手续通知书`（08-17）与 **`400002 实用新型专利证书`（09-08）** 都在，而它们的 `CaseInfo` 里 `AuthorizeDate` / `CertificateDate` / `CertificateNo` / `IssueDate` / `IssueNo` **全部为空**，`CaseStatusType` 仍是 `3 审查中`、`IsFinishCase=false`。

> **结论：案卷字段是纯人工登记字段，滞后可以无限期。判断「授权 / 获证」只能用官文清单（第三节 3.4 + 3.7），不要用案卷字段。**

### 4.1 列表行的同名键恒为 `null`（坑）

`GetPersonalCase`（五个页签）的行里**同样有** `AuthorizeDate`、`AuthorizePostDate`、`CertificateDate`、`CertificateNo`、`IssueDate`、`IssueNo`、`PublicDate`、`PublicNo` 这些键，但实测**一律是 `null`**。

- ❌ 不要用列表行判断是否授权；
- ✅ 要案卷口径的值，改用 `GetUpdateCaseInfo`。

## 五、所内案件状态（`/CaseStatus/*`）

案件行只给 `CaseStatusId` + `CaseStatusType`，名字要自己对上字典：

```bash
curl -sS -k --get "$API/CaseStatus/GetCaseStatus" \
  -H "Authorization: $TOKEN" -H 'Language: zh-CN' \
  --data-urlencode "pageIndex=1" --data-urlencode "pageSize=100"
```

字典每行：`CaseStatusId`、`Code`、`CodeName`、`NameLanguage[].Value`、`IsDefault`、`Sort`、`CaseTypeCodeList` 等（本账号 56 条）。**可读状态名在 `NameLanguage[].Value`**，不在顶层字段。

实测：某案 `CaseStatusId=a750af0a-…` → `NameLanguage[0].Value = 一通回案实审`，`Code=3`、`CodeName=审查中`；而字典里**已经存在**「待领证」(`Code=4`) 这类状态。

> 结论：所内状态是**人工推进**的，官方授权不会自动改它。要判断授权，用第二节；要看所内办理进度，用本节。
>
> `GET /CaseStatus/GetCaseStatusById` 用 `id` / `caseStatusId` / `Id` 三种参数名均返回 `系统错误: e`，参数名未定；取整表在客户端匹配即可。

## 七、推荐做法

| 目标 | 请求量 | 做法 |
| --- | --- | --- |
| **只要官方结论（授权/驳回），不看文件** | **1~2** | 要「提醒」：`GetCaseNewTrendsStatisticsCount` 看 `ItemType=2/5`（近 7 天）。要「按案确认」：`GetNoticeListByCaseId` 按 3.7 表判读（不受窗口/订阅限制） |
| 只看「有没有新授权/获证」 | **1** | `GetCaseNewTrendsStatisticsCount`，比对 `ItemType=2/8` 的 `Count` 与本地上次快照 |
| 还要知道是哪些案子 | 2 | 再调 `GetCaseNewTrendsDetailList`（`ItemType=2`，窗口按需），按 `CaseNo` 匹配本地案件 |
| 要拿到授权通知书 | +1~2 | 用明细行的 `NoticeId` 调 `GetNoticeById` 取 `FileList`，再 `FileStorageGetFile` 下载（第三节） |
| 要判断是否已进案卷 | +1 | `GetNoticeListByCaseId` 看 `NoticeStatusName`（200 待导入 / 300 已导入） |
| 要落到本地案卷 | +N | 命中后再按 `caseId` 取 `GetUpdateCaseInfo` 与文件清单 |

与 [14-只读-增量与变更检测.md](./14-只读-增量与变更检测.md) 的分工：**案件新动态 = 官方案件状态**（受理/授权/审查意见/补正/驳回/获证…），**不含文件上传**；文件级变更仍走 14 章的计数与日期筛选。
