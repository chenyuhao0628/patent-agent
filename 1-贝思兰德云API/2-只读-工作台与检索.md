## 2.1 工作台：五个页签

> **前置**：已完成 1.1 的 Token 设置。无需 ID。

**一个接口覆盖全部五个页签**，靠三个字段切换。

```bash
curl -sS -k -X POST "$API/CaseInfo/GetPersonalCase" \
  -H "Authorization: $TOKEN" -H "Origin: $ORIGIN" \
  -H 'Language: zh-CN' -H 'Content-Type: application/json' \
  -d '{
    "PagedInfo": {"pageIndex": 1, "pageSize": 20},
    "ProcStatusTypeList": [0],
    "TableType": 50010,
    "ActiveName": "waitHand",
    "SelectedProcIdGroup": []
  }'
```

页签参数对照：

| 页签 | `ActiveName` | `TableType` | `ProcStatusTypeList` | 含义 |
| --- | --- | --- | --- | --- |
| 待办 | `waitHand` | 50010 | `[0]` | 待处理 |
| 待审核 | `auditing` | 50011 | `[200]` | 审核中 |
| 待递交 | `waitDeliver` | 50012 | `[300]` | 待递交 |
| 递交中 | `delivering` | 50013 | `[400]` | 已创建递交实例 |
| 已完结 | `finish` | 50014 | `[500]` | 已办结 |

三个字段要**同时**按页签取值。`TableType` 不参与结果过滤，但决定服务端返回的列配置，写错会导致导出与列显示异常。

`SelectedProcIdGroup` 来自子页签（见 2.2），空数组表示不过滤。

### 列表行的字段

列表每行返回**完整字段集**（约 370 个），覆盖案件基本信息、期限、流程状态、客户、申请人、发明人、费用等，但**大部分字段在当前数据下为空**。

实用字段：

| 字段 | 说明 |
| --- | --- |
| `CaseId` / `CaseProcId` | 后续查询用的 ID |
| `CaseHandId` | 递交实例 ID，**仅递交中的行有值** |
| `CaseNo` / `CaseName` / `ClientName` / `ApplyType` | 基本展示信息 |
| `CaseProcName` / `CaseProcNameInfo.CaseProcName` | 当前流程名 |
| `CaseProcLegalDate` / `CaseProcCustomDate` | 法定期限 / 内部期限 |
| `CaseProcCurrentStatus` / `CaseProcCurrentFlowName` | 流程状态与当前节点 |
| `CaseProcUndertakerUserName` | 承办人 |
| `CaseRemark` / `FlowRemark` / `CaseProcProcNote` / `CaseProcOfficeNote` | 各类备注 |

> 需要"剩余天数""卡在谁那里"这类计算结果时，不要依赖列表内的同名字段（详见 2.4、2.5）。

### 列表是按「流程」返回的，不是按「案件」

同一个案件的不同流程（提出申请、请求实审、补正、答复审查意见等）会**各占一行**，因此列表行数对应的就是流程数。

`GetPersonalProcStatistics` 与 `GetPersonalCaseSubTabStatisticsCount` 统计的同样是流程数，两者口径一致。

- **统计"办了多少件"时，直接使用返回行数**，与系统界面显示的数字保持一致；自行去重会导致对不上。
- **需要案件粒度时**，用返回的 `CaseId` 分组即可。

## 2.2 计数与分布

> **前置**：已完成 1.1 的 Token 设置。无需 ID。

```bash
# 各状态计数 -> [{"Code":0,"Count":18}, {"Code":400,"Count":7}, ...]
curl -sS -k --get "$API/CaseInfo/GetPersonalProcStatistics" \
  -H "Authorization: $TOKEN" -H 'Language: zh-CN'

# 工作台页签计数（含工作组维度）
curl -sS -k --get "$API/CaseInfo/GetCaseHandInfoTabCount" \
  -H "Authorization: $TOKEN" -H 'Language: zh-CN'

# 子页签分布（按流程环节）
curl -sS -k --get "$API/CaseInfo/GetPersonalCaseSubTabStatisticsCount" \
  -H "Authorization: $TOKEN" -H 'Language: zh-CN' \
  --data-urlencode 'caseProcStatusType=400'
```

`GetPersonalProcStatistics` 的 `Code` 与 2.1 的 `ProcStatusTypeList` 取值一致（0 / 200 / 300 / 400 / 500）。

`GetPersonalCaseSubTabStatisticsCount` 返回：

```json
[{"ProcId": "...", "ProcName": "提出申请", "ProcCount": 5}, ...]
```

把选中的 `ProcId` 填入 `SelectedProcIdGroup`，即可按流程环节过滤列表。

## 2.3 案件检索

> **前置**：已完成 1.1 的 Token 设置。无需 ID；检索条件全部可选。

检索条件与 2.1 的请求体**写在同一个对象里**，与页签字段并列。

> ⚠️ **检索只在当前页签范围内生效。** 想跨状态查一个案号，需要对多个页签分别请求（通常遍历 `waitHand` → `delivering` → `finish`），再合并结果。
>
> 例如按案号搜 `202606292-0634`：它在递交中，用 `ActiveName=waitHand` 请求会返回 0 条，必须用 `ActiveName=delivering`。

### 跨页签检索

下面的脚本对全部五个页签发起同一组检索条件，合并后按 `CaseId` 标注状态，直接输出结果。

```bash
SEARCH_KEY='<案号 / 案件名 / 客户名关键词>'

python3 - "$SEARCH_KEY" <<'PY'
import json, os, sys, urllib.request

API = 'https://cloudapi02.baselandtec.com/v1'
ORIGIN = 'https://cqgd.baselandtec.com'
TOKEN = open(os.environ.get('TOKEN_FILE', '/tmp/baseland_token'), encoding='utf-8').read().strip()
KEYWORD = sys.argv[1] if len(sys.argv) > 1 else ''

TABS = [
    ('waitHand',    50010, 0,   '待办'),
    ('auditing',    50011, 200, '待审核'),
    ('waitDeliver', 50012, 300, '待递交'),
    ('delivering',  50013, 400, '递交中'),
    ('finish',      50014, 500, '已完结'),
]

def fetch(active_name, table_type, status_type):
    body = {
        'PagedInfo': {'pageIndex': 1, 'pageSize': 100},
        'ProcStatusTypeList': [status_type],
        'TableType': table_type,
        'ActiveName': active_name,
        'CaseNoOrCaseNameOrClientName': KEYWORD,
    }
    req = urllib.request.Request(
        API + '/CaseInfo/GetPersonalCase',
        data=json.dumps(body, ensure_ascii=False).encode(),
        headers={
            'Authorization': TOKEN, 'Origin': ORIGIN,
            'Referer': ORIGIN + '/login.html', 'Language': 'zh-CN',
            'Content-Type': 'application/json',
        },
        method='POST',
    )
    with urllib.request.urlopen(req, timeout=30) as resp:
        data = json.loads(resp.read().decode('utf-8'))
    if not data.get('IsSuccess'):
        raise SystemExit('查询失败: {}'.format(data.get('Message')))
    return data.get('DataList') or data.get('Data') or []

hits = []
for active_name, table_type, status_type, label in TABS:
    for row in fetch(active_name, table_type, status_type):
        hits.append((label, row))

if not hits:
    print('未找到匹配「{}」的案件。'.format(KEYWORD))
else:
    print('命中 {} 条：'.format(len(hits)))
    for label, row in hits:
        proc = (row.get('CaseProcNameInfo') or {}).get('CaseProcName') or row.get('CaseProcName') or '—'
        print('  [{}] {} | {} | 流程 {}'.format(
            label, row.get('CaseNo'), str(row.get('CaseName'))[:28], proc))
PY
```

同一案号可能在多个页签同时命中（例如既有待办流程又有已完结流程），这正是需要合并多个页签的原因。

```bash
curl -sS -k -X POST "$API/CaseInfo/GetPersonalCase" \
  -H "Authorization: $TOKEN" -H 'Language: zh-CN' \
  -H 'Content-Type: application/json' \
  -d '{
    "PagedInfo": {"pageIndex": 1, "pageSize": 20},
    "ProcStatusTypeList": [0],
    "TableType": 50010,
    "ActiveName": "waitHand",
    "CaseNoOrCaseNameOrClientName": "关键词",
    "LegalStartDate": "2026-01-01",
    "LegalEndDate": "2026-12-31"
  }'
```

可用检索字段：

| 字段 | 用途 |
| --- | --- |
| `CaseNoOrCaseNameOrClientName` | 案号 / 案件名 / 客户名 综合模糊搜索 |
| `CaseNos` + `IsCaseNoFuzzySearch` | 案号列表，可模糊 |
| `ApplicantNo` + `IsApplicationNoFuzzySearch` + `IsApplicationNoRemoveDotCN` | 申请号，可模糊、可去 `.CN` |
| `CaseName` / `ClientCaseNo` | 案件名称 / 客户案号 |
| `ApplyTypeClassifyList` + `ApplyTypeCodeList` | 申请类型分类与代码 |
| `ApplicantIdList` | 申请人 ID 列表 |
| `ClientFilingStartDate` / `ClientFilingEndDate` | 客户来案日期区间 |
| `LegalStartDate` / `LegalEndDate` | 法定期限区间 |
| `CustomStartDate` / `CustomEndDate` | 内部期限区间 |
| `CaseCreateDateStart` / `CaseCreateDateEnd` | 立案日期区间 |
| `HandStartDate` / `HandEndDate` | 递交日期区间 |
| `FinishDateStart` / `FinishDateEnd` | 完结日期区间 |
| `CaseProcProcessIdGroup` / `ProcIdGroup` | 流程环节 |
| `IsUndertakerAuditing` / `CaseLabel` / `ContactUserName` | 承办审核 / 标签 / 联系人 |

**三个复选框字段要传布尔值**，不要传数组：

```text
IsCaseNoFuzzySearch        true / false
IsApplicationNoFuzzySearch true / false
IsApplicationNoRemoveDotCN true / false
```

需要总数时用同一份检索条件调用 `GetPersonalCaseCount`。

## 2.10 工作组视图

2.1 是**个人视图**（只看自己经办的案件）。工作组视图是另一套接口，用于查看**整个工作组的案件**，两者数据不重叠。

### 页签与 TableType

| 页签 | `ActiveName` | 工作组 `TableType` |
| --- | --- | --- |
| 待处理 | `waitStartAudit` | 40010 |
| 待审核 | `waitAudit` | 40012 |
| 待递交 | `wait2Official` | 40017 |
| 办理中 | `auditing` | 40013 |
| 委托第三方 | `auditingThirdParty` | 40014 |
| 审核完成 | `finishAudit` | 40015 |

### 请求

```bash
curl -sS -k -X POST "$API/CaseInfo/GetCaseHandInfoListOfProcessing" \
  -H "Authorization: $TOKEN" -H 'Origin: $ORIGIN' \
  -H 'Language: zh-CN' -H 'Content-Type: application/json' \
  -d '{
    "IsWorkAgent": true,
    "UserTableTitleColumnList": ["CaseNo","CaseName","ClientName","CaseProcName",
                                 "CaseProcCustomDate","CaseProcLegalDate","CaseProcUndertakerUserName"],
    "TableType": 40013,
    "PageInfo": {"pageIndex": 1, "pageSize": 20, "SortField": null, "SortType": null}
  }'
```

按页签替换路径与 `TableType`：

```text
/CaseInfo/GetCaseHandInfoListOfStart        40010
/CaseInfo/GetCaseHandInfoListOfPending      40012
/CaseInfo/GetCaseHandInfoListOfWaitSend     40017
/CaseInfo/GetCaseHandInfoListOfProcessing   40013
/CaseInfo/GetCaseHandInfoListOfEntrustCase  40014
/CaseInfo/GetCaseHandInfoListOfFinish       40015
```

### 请求字段

| 字段 | 说明 |
| --- | --- |
| `IsWorkAgent` | 是否工作组视图，固定 `true` |
| `UserTableTitleColumnList` | 需要返回的列 |
| `TableType` | 按上表取值 |
| `PageInfo` | **必需**，缺了会报 `系统错误: e` |
| `IsCaseProcCurrentHandlerNot` | 可选，布尔值，排除当前办理人 |

> ⚠️ **分页字段名与 2.1 不同**：这里是 `PageInfo`（含 `SortField` / `SortType`），2.1 用的是 `PagedInfo`。写错会报 `系统错误: e`。

### 计数

```bash
curl -sS -k --get "$API/CaseInfo/GetCaseHandInfoTabCount" \
  -H "Authorization: $TOKEN" -H 'Language: zh-CN'
```

返回工作台各页签计数，其中 `WorkAgentCount`、`WorkAgentWaitSendCount` 是工作组维度，与 `MyPendingCount`、`MyWaitSendCount` 等个人维度并列。
