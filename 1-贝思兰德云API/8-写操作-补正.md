## 3.5 补正路线：100006 + 逐条补正内容

`100006` 保存的是一张结构化补正表，不能只上传一个 Word 文件，也不能把补正前后文字塞进普通文件接口。

### 选择补正书并读取现有数据

```bash
curl -sS -k --get "$API/CaseInfo/IsHasCaseHandForm" \
  -H "Authorization: $TOKEN" -H 'Language: zh-CN' \
  --data-urlencode "caseHandId=$CASE_HAND_ID" \
  --data-urlencode 'formCode=100006'

curl -sS -k --get "$API/CaseInfo/GetFormCorrection" \
  -H "Authorization: $TOKEN" -H 'Language: zh-CN' \
  --data-urlencode "caseHandId=$CASE_HAND_ID"
```

未选中时先调用 `AddCaseHandForm(caseHandId,100006)`。已有数据时必须先读取，保留服务器返回的已有内容和 ID，再进行修改。

### 选择补正原因

页面有两个主要原因：

1. `CorrectionReasonType=1`：依据专利法实施细则第 57 条，对申请主动提出修改。
2. `CorrectionReasonType=2`：依据专利法实施细则第 50 条，针对国家知识产权局发出的通知书进行补正。

选择第 2 项时，先读取关联通知书（见 2.7）：

```text
PostDate   → Correction.NoticeDate
NoticeName → Correction.NoticeName
FaWenXLH   → Correction.NoticeNo
```

补正页面源码在"获取通知书"后会去掉通知名称中的"通知书"字样；命令行应保持与页面同样的值，不能把日期、名称、发文序号错填到补正条目中。第 1 项主动修改不需要通知书三字段，但仍需选择补正原因。

### 填写 CorrectionContentList

页面还强制要求选择"是否为补委托书"：`IsAddEntrust=true` 或 `false`，**不能留空**。

每一条补正内容都必须单独维护以下四项：

```json
{
  "ChangeId": "<客户端生成的唯一 ID>",
  "Sort": 0,
  "FileName": "权利要求书",
  "PositionInFile": "权利要求 1",
  "CorrectionBefore": "补正前原文",
  "CorrectionAfter": "补正后文字"
}
```

`FileName` 使用页面下拉项：`权利要求书`、`说明书`、`说明书附图`、`说明书摘要`、`摘要附图`、`核苷酸或氨基酸序列表`、`其他`。选择第 2 类补正原因时，还允许 `请求书`、`授权委托书`、`主体资格证明`。`PositionInFile`、`CorrectionBefore`、`CorrectionAfter` 都是必填项。

完整对象：

```json
{
  "FormCode": 100006,
  "CaseHandId": "<CaseHandId>",
  "Correction": {
    "CorrectionReasonType": 2,
    "NoticeDate": "<YYYY-MM-DD>",
    "NoticeName": "<页面获取后的通知名称>",
    "NoticeNo": "<发文序号>",
    "IsAddEntrust": false
  },
  "CorrectionContentList": [
    {
      "ChangeId": "<唯一 ID>",
      "Sort": 0,
      "FileName": "权利要求书",
      "PositionInFile": "权利要求 1",
      "CorrectionBefore": "<补正前>",
      "CorrectionAfter": "<补正后>"
    }
  ]
}
```

```bash
# 新增
curl -sS -k -X POST "$API/CaseInfo/InsertFormCorrection" \
  -H "Authorization: $TOKEN" -H 'Language: zh-CN' \
  -H 'Content-Type: application/json' \
  -d "$CORRECTION_BODY"

# 已有记录时改用：POST /CaseInfo/UpdateFormCorrection
```

保存后重新读取 `GetFormCorrection`，确认 `Correction` 和 `CorrectionContentList` 均存在，且每条记录四个文本字段都有值。除非页面另外出现某个需要附件的独立表单，否则不要为 `100006` 额外上传一份"补正书 Word"来代替这张表。
