## 安装

当前安装制品以 `release/release-manifest.json` 中的 `0.15.2` 为准；已有 `0.14.0` 和 `0.15.1` 制品及对应历史清单原样保留：

- macOS Apple Silicon：`.pkg` 或 `.app`
- Windows x64：NSIS `.exe`

安装器沿用固定应用标识，覆盖程序并保留用户数据。Mac 安装到所选安装域的 Applications。Windows 保留安装路径和 AppData。当前包没有发行签名、macOS 公证，也没有在线自动更新。

账号、加密凭证和本机设置在应用数据目录。原始申请库与工作目录单独选择。

## 案件

每案只有一个当前办理。案件库可搜索、筛选、排序、调整列宽、批量归档，并按当前状态查看。

同步范围是当前账号负责的案件。启动、登录和选定工作目录后会增量同步。案件库「刷新案件」重新扫描个人案件列表，用于发现新分配案件、归属变化和此前未知的个人流程。案件内「刷新本案」只更新当前案件的已知个人流程、附件清单、备注、流程明细和官方结论；以不可变 `FileNo` 识别远端材料，只下载新增或尚未就绪的文件，远端文件名变化只更新显示信息，不改动其他案件。没有固定周期的自动同步。

原始申请库只读。匹配结果复制到案件目录，原件保留。

期限显示来源。提出申请使用内部期限；其他业务优先使用官方期限，否则使用贝思兰德计算期限。

官方回执进入「等待官方」，不等于结案。授权或驳回出现后，案件离开该列表，状态显示结论本身。未见结果只表示官文清单里没有对应结论，不是未授权。

只在读到明确结案标记后做本地归档，不向贝思兰德写入结案。

工作目录迁移先预览、复制和校验，再切换。设置里可以整理当前账号的系统生成目录和成果文件名；未知目录、冲突、符号链接和用户文件不动。

## 答复、撰写与审查

答复和补正在「本案对话」办理。步骤是材料核对、策略讨论、起草修改、可选独立复核、用户定稿。默认办理当前步骤，也可以只讨论。

分析完成前不能选定策略，选定前不能起草。采用稿、修改正文或补正字段会形成新版本，并使旧复核失效。定稿前可以微调正文和补正条目。未保存的微调会阻止确认定稿。定稿可以撤销，已有正文、补正和定稿记录保留。

停止或退出后保留已输出内容。继续使用当前上下文，重试在新分支执行。切换分支不回滚案件文件。

撰写从技术交底开始，按五个阶段确认。参考材料从本机复制到 `01_通知与材料/撰写参考/`，支持 DOCX、DOC、PDF、TXT、Markdown、PNG、JPEG，每次 1–12 份，每份不超过 20MB。只有本次勾选的材料进入任务；离开页面后再次进入须重新选择。移出列表不删除磁盘副本。

审查使用独立上下文和指定稿件版本，可选，不阻塞定稿和提交。

## 提交

提交页在贝思兰德流程之后。程序准备材料和表单，用户核对后再保存、回读并转交下一内部办理人。

补正没有单独的说明 Word。逐条补正在「本次材料」填写，可先存为本机草稿；保存到贝思兰德时写入补正表。答复使用意见陈述书和本次修改部分。提出申请要求完整五书。

保存、内部转交和官方递交是三件不同的事。保存中断后刷新并按原办理节点、原接收人回读，不自动再次转交。清理远端草稿必须回读确认目标文件关联和补正条目确已清空；部分完成时保持锁定并继续核对。已转交的事项不能重复转交。

另一台已登录的电脑可以读到服务端已经保存的材料和表单。本机没有文件时，可以按不可变 `FileNo` 下载远端稿件查看；文件名仅作为展示标签，同名文件不用于猜测身份。

## 稿件与公式

界面用离线 KaTeX 显示公式。导出的申请文件和答复文件使用随应用提供的 Word 模板，公式写入 Word 可编辑公式。从 DOCX 读取时保留 OMML 公式、段落、表格、分节页眉和可支持图片；修订痕迹、旧公式域及其他不能无损解释的结构会明确报错，不以遗漏内容的纯文本替代。

附图和复杂公式使用已经核对的 Word 文件。文字或公式渲染不能代替图形验收。

对比文件来自通知中的公开号，经智慧芽下载到当前轮次。凭证按账号加密保存。扫描页、不完整公开号和非专利文献需要人工核对。

## 工具

设置 → 文档工具有四项：联网检索、软件下载、任意命令与软件安装、预设转换组件自动安装。下载和任意命令默认关闭。联网检索默认开启。修改这些设置前先停止正在运行的任务。

任意命令以本机当前用户权限执行，可以访问其他文件和网络。它不是沙箱，也不受检索、下载开关限制。应用不把凭证或整个案件库放进命令环境。

命令记录保存在对应任务的 `tool-audit`。停止任务会结束由该任务启动的命令；已经独立打开的图形程序不保证随任务关闭。

技能和 MCP 在设置中导入、编写、启停和测试。本地 MCP 需要先开启任意命令。扩展配置留在本机，不随案件目录迁移。

诊断日志可用「导出最近 10 分钟日志」保存到本机。日志不包含密钥、请求正文、案件正文和完整路径。

## 开发

```sh
npm ci
npm test
npm run build
npm run desktop
npm run package:release
```

`npm test` 运行领域、主进程和打包脚本的自动化测试。`npm run build` 包含类型检查。打包前在 `.lab/agent-runtime` 准备固定版本的 OpenCode。打包失败时保留上一版安装包。

自动化通过和安装包生成，都不代替真实模型质量验收。2026-09-28 用户实测确认：Windows 实机、覆盖安装与贝思兰德真实写入均可用（写入存在若干实测 bug）；问题记录与修复见 `EXEC_PLAN.md`。
