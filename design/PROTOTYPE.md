## 参考与设计系统

已浏览 [Linear 项目规划](https://linear.app/plan) 的项目概览与任务分层，以及 [Craft 整理](https://www.craft.do/zh-CN/organize) 的空间与目录组织。专利业务流程来自本项目已确认需求。

内置 Image Gen 生成 [单案概览 v2](case-overview-v2.png)、[答复编辑 v2](reply-editor-v2.png) 和 [独立审查 v3](independent-review-v3.png)，均为 1536×1024。旧 [平铺初版](workbench-concept.png) 已被用户否定，仅保留作历史记录。

设计主线：全局案件库 → 单案空间 → 具体业务。概览只保留当前工作、业务入口和案件信息；编辑与审查页优先展示正文，材料与辅助操作按需展开。撰写、答复和独立审查共享案件归属，成果与内部流转承接已确认版本。

令牌：白色主区 #ffffff、外背景 #f6f7f9、导航 #f0f1f5、正文 #232631、辅助 #808695、主色 #625de8、浅紫选中。控件圆角 8px、工作表面 12px；PingFang SC / 系统无衬线，文档标题衬线；Lucide 同风格描边图标。全局导航约 210px、顶栏 56px，普通页面约 40px 留白，编辑页面适当压缩。

## 页面覆盖与设计决定

| 页面 | 已实现的原型交互 | 后续接入位置 |
| --- | --- | --- |
| 案件库与导入 | 搜索、业务状态筛选、期限排序、两周内到期、批量归档与恢复；单案 / 批量导入、整理步骤、下载失败与重试示例 | 通知识别、真实下载、案件去重与目录管理 |
| 单案概览与材料 | 当前工作入口、各业务独立标签、本案实际原型成果；材料列表与详情、轮次切换、待补充状态、格式示例 | 原件、有效版本、正文及页图索引 |
| 答复 | 材料人工确认 → 分析 → 策略选择 → 修改与版本 → 独立复核 → 人工定稿；多讨论、暂停与恢复 | 按类型组合的 DSH 规则、公开结构化 agent 接口 |
| 撰写 | 技术交底、必要检索示例、方案选择、四份申请文件编辑、版本保存、送审、冻结定稿、继续修改 | 交底分析、检索、撰写模型与指定模板 |
| 独立审查 | 选择文件来源、锁定版本、问题清单、对应文件原文高亮、处理意见、审查结论、返回工作稿；历史审查记录保留 | 独立模型与真实证据定位，不依附答复 |
| 成果与内部流转 | 答复 / 撰写定稿目录；内部审查记录另列；选择成果 → 表单 → 办理人 → 核对转交；本机模拟回执可重开查看 | 贝思兰德文件 / 表单保存、内部转交及服务端业务回读 |
| 工作任务 | 各案答复、撰写、审查及流转记录；进行中、暂停、完成过滤；回到对应案件 / 轮次 | 后台任务事件、真实取消与恢复 |
| 设置 | 模型、文件目录、Word 模板、技能 / MCP、更新五个分组；非敏感偏好保存、扩展示例开关 | 凭证安全存储、路径选择、模板版式、真实扩展和升级 |

工作稿与审查快照分开；修改后不能沿用旧审查定稿。重新审查保留旧问题与处理记录，继续修改保留先前定稿成果。材料缺失会阻止开始答复。内部转交只选择已确认成果，内部说明不自动进入对外文件。

## 视觉验收

逐一用浏览器实际运行页面，并使用图像查看工具检查概念图和真实截图。桌面检查覆盖概览、材料、答复、撰写、审查、成果流转、任务与设置；导入检查包括批量失败状态。

| 五项对照 | 验收结果与必要偏离 |
| --- | --- |
| 整体结构 | 全局导航、案件空间、本案业务和阶段导航各自分层；案件列表不与详情同屏。独立审查采用左原文、右问题，与概念结构一致。 |
| 视觉权重 | 概览只有一块当前工作重点；编辑页缩小重复标题。审查阶段与标题同排，处理按钮保留在检查栏底部。 |
| 留白与密度 | 材料列表 / 详情分栏，设置采用分组目录。审查原文和问题详情独立滚动，避免所有内容纵向铺开。长表单仍采用正常页面滚动。 |
| 颜色与字体 | 白色表面、浅灰导航、单一紫色主要操作；统一系统字体与图标，文档标题使用衬线。保留 v2 导航标识，未采用 v3 概念图自行生成的新标志。 |
| 文案与操作 | 用实际原型状态驱动当前工作、文件、版本和任务。概念中虚构的账号头像、通知和全局搜索未加入；按钮反映当前阶段和可用操作。 |

文案差异：概念图示例 v2 改为当前保存版本；“原文定位”用问题点击后切换文件、原文高亮及滚动表达。问题内容来自固定虚构样例，界面明确标注交互示例。撰写采用可编辑文本和文件目录，附图仍是目录示例；定稿下载为 JSON，不将其称为模板 Word。

本轮桌面 DOM 视口实际为 1280×720，截图服务输出约 1265×712 JPEG。请求 1536×1024 原生覆盖未能改变本轮标签页，已复位；因此本轮不声称与 1536×1024 概念图逐像素一致。旧 v2 同尺寸截图作为历史记录保留。

390×844 的 [内嵌验收页](../evidence/responsive-check.html) 检查案件库、撰写、审查、成果与设置，内容宽度与滚动宽度均为 375px（扣除滚动条），无页面横向溢出。全局导航图标化，阶段和文件目录局部滚动，主附栏纵向排列。此前还检查了概览与答复。此项是浏览器内嵌 CSS 视口验证，不是手机或安装包验收。

## 自动化与实际操作证据

最终 `npm run build` 通过；`npm test` 7 项通过，覆盖答复确认 / 策略门槛、停止后的旧完成事件、复核版本失效、定稿保护、案件 / 轮次隔离，以及撰写审查快照、审查历史和先前定稿保留。

在隔离的 `?qa=1` 数据中完成：

- 交底 → 检索示例 → 方案 → 四份申请文件 v1 → 独立审查；逐项记录意见，第二项切换到说明书并高亮对应原文；结论完成后返回撰写，人工冻结定稿。
- 成果库读回四份撰写文件与答复定稿；选择两份文件、核对表单与示例接收人后模拟转交，刷新仍能查看记录与接收人。
- 批量创建两案，演示下载失败使完成按钮不可用，重试后导入；两案批量归档，再恢复。
- 将材料标为待补充后，即使勾选核对，开始答复仍不可用；原件和既有成果保留。
- 保存目录与扩展示例配置，刷新后保留；任务中心的撰写记录能回到对应案件。
- 既有答复验证：停止 / 重开暂停 / 人工恢复、策略选择、人工编辑保存与重开、历史只读、复核处理门槛、定稿入库、任务轮次定位和模型名称偏好持久化。v3 再检查了答复入口。

视觉检查过程中发现滚动副作用误返回 Promise 会引发 React 清理错误，已改为不返回值；修复后重新打开页面并完成上述管理与跨模块操作，最后独立检查标签页的错误日志为空。自动化结果不能代替真实模型、真实材料或安装验收。
