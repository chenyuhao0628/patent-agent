# 0.20.0 候选测试版：安装与工作台稿件保存验证

2026-10-09。本版供实机验证多文件及工作台保存链路。合成测试和安装包校验通过，不代表已证实并解决原来的真实服务故障。

## 安装

1. 保存正在编辑的文件，正常退出旧版专利工作台。保留当前案件目录与已有稿件，不必卸载或删除应用数据。
2. macOS Apple Silicon 双击 `release/PatentWorkbench-0.20.0-macOS-arm64.pkg`，选择与旧版相同的安装域；Windows x64 双击 `release/PatentWorkbench-0.20.0-Windows-x64-Setup.exe`，沿用已有安装目录。只安装正在测试的那一平台。
3. 从安装完成的应用启动，确认是 0.20.0，避免继续打开旧包中的应用。macOS 可以从“专利工作台 → 关于”查看；两平台均可在“设置 → 诊断日志”导出的 JSON 中核对 `appVersion`。
4. 确认原案件、工作目录与稿件仍可读取。旧版 0.19.1 安装包保留在 `release/`。当前候选包沿用原来的未发行签名 / 未公证方式；若出现系统拦截，请记录完整提示，不需要为测试关闭全局安全设置。

## 先验证一次工作台保存

1. 选择你有权办理、确实需要保存本次修改、尚未内部转交的案件，核对案件和当前流程。先测试“保存材料”，不要为了排查直接转交下一办理人或递交官方。
2. 若仍显示旧版“等待远端核验”，先点击“刷新核对结果”查看现状并保留旧提示。确认只是保存失败、没有已发出的内部转交，再通过“返回草稿重新整理”进入编辑。不要连续重复保存。
3. 点击“重新获取工作台稿件”，使这次方案按新版重新准备；旧方案和文件副本保留。仅升级应用不会把旧方案里的合并稿自动变成独立分件。核对显示的稿件版本。
4. 若本次同时修改说明书和权利要求书，应看到独立的“修改后说明书”“修改后权利要求书”，以及“意见陈述书 Word”三份文件。分别预览，核对内容、修改范围和权利要求项数；不需要再选择合并申请稿。
5. 核对本次五书勾选、通知书字段及下一办理人。保存确认框会明确本次保留和移除的材料范围，核对无误后点击“确认保存”。
6. 成功标准有两项：工作台显示“已保存，等待内部转交”；贝思兰德同一案件、同一递交实例中可找到并打开本次两份修改文件及意见陈述书，内容和版本正确。只看到进度结束或 HTTP 成功不算通过。
7. 保存成功后先退出并重开应用，刷新确认材料和已保存状态仍在。此时完成本轮保存验证；内部转交按实际业务需要另行执行。

## 如果仍失败

- 保留完整红色错误文字和其上方分阶段记录，尤其最后成功的一步（文件存储、分件关联、表单或回读）；记录发生时间和操作来源。可以截图反馈，不必提供密钥或整案材料。
- 立即在“设置 → 诊断日志”导出最近 10 分钟日志；macOS 也可用“帮助 → 导出最近 10 分钟日志…”。日志只有运行元数据，需要与页面错误及阶段记录一起判断，不能仅凭日志推断文件内容问题。
- 在贝思兰德查看是否已经出现部分文件，先刷新核对，不自动重试保存、不自动删除或转交。
- 本地成功时使用的是另外编辑的文件，不能与工作台生成文件直接视作同文件对照。若需进一步 A/B，先保存失败证据，再在明确的测试范围内使用完全相同的文件、文件类型、表单与材料勾选，分别记录每次服务端初始状态；不要为做对照反复覆盖正式案件。
