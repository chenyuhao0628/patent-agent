## 已有验收证据

全量 840 项自动化测试、类型和生产构建通过。真实 OpenCode 二进制配合本机合成供应商，完成四种模型协议、工具权限、跨案拒绝、数据库复制、会话续接、停止、缓存统计和强制压缩隔离检查。最终 .app 实际完成三轮同案讨论（中途正常退出重开）、每轮压缩、停止及第二案件隔离；不同案件的后台会话和缓存键不同。详见 [阶段 5 报告](../evidence/opencode-v2-migration/phase-5/RESULT.md)。

## 现场验证

1. 打开“设置 → OpenCode 后台”，核对实际版本以及“自动检查并安装兼容更新”。默认在启动时和运行期间每 6 小时检查，候选先用合成数据验证，无任务运行时切换；存在上一版时可回退。
2. 在一个合成案件中完成一次“本案对话”，展开任务中的“会话与上下文缓存”，记录会话 ID。继续同一讨论并正常退出、重开后续办，核对公开历史、已保存产物和“已接续”状态。
3. 在另一案件重复讨论，确认会话 ID 不同。材料、稿件版本、办理阶段、模型或讨论分支变化可能建立新上下文，原记录仍保留。停止或失败后的隐藏执行不直接复用。
4. 在模型实际开始响应后点击“停止”，确认任务停止且不再产生工具写入；重开后从公开记录和已核验产物继续。
5. 配置实际供应商后观察缓存用量。允许缓存、会话保留和供应商实际命中是不同结果；供应商未报告命中时界面如实显示。定时付费预热保持关闭，本轮合成 token 数不代表真实命中率或费用。

Windows 现场还需验证安装、双击启动、菜单、子进程树停止和退出恢复。真实案件内容质量、真实供应商长任务、用户指定 Word 模板的复杂版式及贝思兰德生产写入，继续按各自授权和证据验证；本轮不将合成检查作为这些业务的通过结论。

依赖审计为 0 high、10 moderate，剩余节点源自同一 `sprintf-js` 上游告警；实际桌面 bundle 不含该依赖链，构建链告警保留，见 [阶段 4 记录](../evidence/opencode-v2-migration/phase-4/RESULT.md)。
