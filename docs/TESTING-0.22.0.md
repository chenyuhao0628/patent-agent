- 864 项自动化、类型与生产构建；旧数据、保存顺序、账号 / 案件 / 阶段保护、适配器合同均有回归。
- 全局 / 单案分别注册、统一宿主和统一数据入口；隔离源码副本真实生成两个位置的面板，2 项生成模块测试、构建及原生加载通过。
- 默认及替代测试适配器走同一装配入口；真实 OpenCode 二进制配合合成供应商完成四协议、会话保留、隔离、压缩和取消检查。
- 实际最终 .app 的入口、保存 / 重开、任务切页 / 停止、1280×800、1440×900、1920×1080 视口分别记录。
- 与 0.21.0 对照页面冷 / 暖打开、全局 / 单案刷新、保存可见 / 落盘、固定供应商任务耗时。发现的懒加载额外等待和空目录多案同步竞态已修复，见 [性能报告](../evidence/module-platform/phase-6/PERFORMANCE.md)。

完整结果见 [最终报告](../evidence/module-platform/phase-6/RESULT.md)。合成供应商不是付费真实模型，缓存统计不代表真实命中率或质量；模块模板不是任意外部插件安装器。

## 现场检查

1. 保留现有案件目录和应用数据，启动后核对版本 0.22.0。案件库为全局视图，打开某案后页签只显示该案内容。
2. 在独立合成案件编辑标题、标签或工作稿，切回案件库并退出重开，核对显示及实际文件；不要用正式案件试验覆盖保存。
3. 启动本案任务后切换到案件库，再回到所属案件检查进度；主动停止后确认不再执行，重开不会自动重放已停止任务。
4. 同案的当前办理保持唯一，历史记录只读；无效旧书签明确提示，不能自动读取当前稿件。
5. 设置中查看 OpenCode 后台自动兼容更新和会话 / 缓存统计。不同案件、阶段和分支保持隔离，已完成同范围会话可以重开续接。

Windows 启动、安装、菜单、子进程停止和退出恢复仍需实机。真实供应商长任务、实际缓存收益、指定 Word 模板的复杂版式及贝思兰德生产写入须依各自授权验证。此前用户报告的真实贝思兰德稿件保存失败，不能由本轮合成结果宣布解决。
