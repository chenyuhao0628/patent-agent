# 公开接口、IPC 与异步作用域

> 当前技术参考；需求以 [需求索引](../../REQUIREMENTS.md) 及其模块细则为准，状态与待办见 [实施计划](../../EXEC_PLAN.md)。代码路径相对仓库根目录。

## 4. 接口标准

### 4.1 公开 API

`DesktopAPI` 组合案件与同步接口、`AgentAPI`、`ProfessionalAPI`、`TransferAPI`、`ModelAPI` 和 `ApplicationAPI`。

各业务接口必须使用明确的输入、输出和任务状态类型；账号、案件、流程范围显式传递。密钥、Cookie 和完整请求头不得出现在公开业务载荷中，不以终端文本猜测任务状态。

### 4.2 IPC 契约

| 文件 | 职责 |
| --- | --- |
| `src/contracts/version.ts` | 契约版本、错误类别与序列化 |
| `src/contracts/ipc.ts` | 通道名称、参数元组、返回值、单向事件载荷 |
| `desktop/ipc-contracts.ts` | 未知输入的运行时解析与字段边界校验 |
| `desktop/ipc-scope.ts` | 各通道作用域策略及入队前身份捕获 |
| `desktop/main.ts` | 请求注册、发送方检查、调度与主进程调用 |
| `desktop/preload.ts` | 按公开契约提供最小桥接 |

实现约束：

- handler 参数和结果通过 `IpcArgs<Name>` / `IpcResult<Name>` 关联，不能用统一 `any` 或无类型参数数组代替。
- 扩展、对比文件和模型动态方法使用明确的方法联合与结果联合。
- 输入拒绝缺字段、错误枚举、非法路径、超长文本及跨账号请求；允许结构上合法的空草稿、空接收人和默认模型参数，最终业务提交另行校验。
- preload 对动态联合响应执行最小结构校验；TypeScript 不能代替跨进程序列化边界的运行时校验。
- 事件核对应用窗口、主 frame、请求标识及账号代际；错误保留稳定类别。
- 主进程是最终授权边界，UI 禁用按钮不能代替服务端和文件操作校验。

### 4.3 保存与异步作用域

公开工作区保存参数为 `[profileKey, workspace, scope]`，`scope` 使用 `DesktopScope`：

| 字段 | 用途 |
| --- | --- |
| `profileKey` | 账号身份 |
| `scopeVersion` | 桌面会话代际 |
| `caseId`、`processKey` | 必须成对出现，限定案件与当前流程 |
| `caseRevision` | 案件阶段修订号；当前渲染层写入携带，兼容类型仍允许省略 |

主进程在请求入队前冻结身份，在执行、跨异步步骤和文件发布前复核账号、目录、案件、修订号与流程。案件从 A 切到 B 再回到 A 时，旧修订号仍然失效。

案件级保存只处理目标案件，不能把同一渲染快照里的其他案件覆盖回去。工作稿、版本文件、manifest 和工作区索引发布均使用相应 guard。

普通同步的时间戳和显示标签不增加案件代际；阶段、权限、归档或官方结论变化才使旧作用域失效。保存返回已提交状态，渲染队列按字段合并后续编辑，并通过 `snapshotVersion` 拒绝同阶段的迟到快照。本案刷新由主进程顺序完成同步、流程、结论和备注，避免自身阶段变化中断后续步骤。

`DesktopService.workspace.cases` 及旧内部服务调用仍承担兼容适配；不能把兼容入口的宽松参数视为公开 IPC 的写入授权。

### 4.4 模型与 Agent

模型运行时只在主进程。任务启动时冻结供应商、模型、协议、推理级别、上下文窗口、工具与技能摘要，以及本案材料快照。

长任务必须提供停止、继续、重试或明确的不可恢复状态。产物有效性由材料读取证据、文件校验与状态机决定，不能只接受模型自述。

### 4.5 阅读证据与任务记忆（0.16.0）

`desktop/agent-evidence.ts` 的任务内台账只接受宿主阅读器实际返回的哈希、页 / 行范围、总范围和文字 / 页图 / 转换来源。重复读取合并区间；私有文字块不通过 MCP 回显为额外元数据。`inspect_evidence` 返回覆盖及待补读范围。

正式 JSON 产物可附 `evidenceCitations: [{id, materialId, hash, unit, start, end, quote?, target?}]` 和 `opinionResponses: [{opinionId, response, citationIds?}]`，各最多 200 项。冻结稿件使用 `materialId=current-draft`，补读调用 `read_draft`；文件材料调用 `read_material`，PDF 的 `startLine/endLine` 表示页码。

| 检查情况 | 处理 |
| --- | --- |
| 正式任务尚未读取选定来源、当前通知已知缺页 / 行 | 同一任务补读具体范围 |
| 不存在的引用、版本不符、越界、未读范围、错误逐字引文 | 保留候选，返回可修复错误 |
| 参考材料只读部分、页图、声明关联的转换结果 | 提示覆盖和无法自动判断的部分 |
| 未提供结构化引用或未逐项标记意见回应 | 提示核对，不新增定稿 / 提交门槛 |

引用只在声明位置的实际文本内匹配，保留数学字符差异；页图不标记为逐字匹配。来源检查不替代实质专利判断。

`src/domain/task-memory.ts` 区分用户原话、界面确认、稿件版本和待决定状态；只使用当前案件 / 分支及适用撰写阶段，独立审查不注入主讨论。上下文整理先缩减旧助手回复，再将超窗旧用户消息转为任务内来源指针；`read_task_memory(id, offset, limit)` 分页读取原文，必须读完被延后的用户输入才能接受结果。当前用户请求不静默截断。

答复、补正、撰写与审查复用质量事件，任务结束、停止或作用域变化后拒绝迟到更新。专业工作流在保存产物时提供校验回调，使模型在退出前可以局部修复。旧记录没有新字段仍兼容读取。

## 0.17.0：任务续办合同

- AgentHost / runner 传递可选 taskContract 与 progress 事件；原任务无字段时兼容。业务进度持久化为任务本机 outputs/task-progress.json 并随任务记录展示。
- artifact-checkpoint.json 升为 schema 2：范围 identity、value 及内容 SHA-256。旧 schema 1 明示缺摘要；范围不符或损坏保留源文件、不复用内容。documents 按子项合并，数组整体替换。
- recovery-files.json 仅收集本任务 command-work 的普通文件，恢复时逐项核对摘要后复制到新任务。最多 100 文件、单文件 20 MiB、合计 80 MiB、深度 12；运行时 HOME / 临时目录不复用，越界 / 符号链接 / 变化文件不复制。共享工具目录、下载区和案件目录不扫描。
- operation-journal.json 保存执行意图、脱敏返回摘要与结束状态；超时 / 停止保留结果不明标记，相同操作不自动重放。回执损坏只阻止相关外部操作自动重试，分项正文仍可补齐。退出码不是业务结果验收。
- inspect_artifact 返回业务进度、工作文件 / 回执；field 读取已有字段，operationId 读取回执返回摘要。恢复后的技能及必要材料仍按当前任务读取核对，不把旧阅读回执冒充本会话已掌握内容。
- ProfessionalCommand 新增 resume(jobId)。主进程校验当前阶段、最新未完成任务、确认记录、材料哈希与审查来源；重启阶段改变 revision。专业任务保留原输入与冻结材料列表，迟到进度不覆盖已结束记录。
- 修复判据累计有效字段、必读范围与最少缺项；重复改写 / 读取、删除再补回不算新进展。达到既有连续停滞限制时保留检查点，用户仍可明确继续。
