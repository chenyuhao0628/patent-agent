# 页面、能力与历史访问

> 当前技术参考；需求以 [需求索引](../../REQUIREMENTS.md) 及其模块细则为准，状态与待办见 [实施计划](../../EXEC_PLAN.md)。代码路径相对仓库根目录。

## UI 标准

### 页面结构

| 层次 | 组件与职责 |
| --- | --- |
| 全局壳层 | `AppShell`：导航、顶栏、同步及错误提示 |
| 页面装配 | `App`、`PageContent`：路由、统一数据和全局 / 单案宿主选择 |
| 面板宿主 | `PanelHost`：注册、访问、组件代码缓存、加载 / 重试和作用域生命周期 |
| 案件空间 | `CaseSpace`：案件内导航、当前办理、历史访问 |
| 业务工作台 | 答复、撰写、独立审查、内部流转 |
| 聚合页面 | 任务、审查队列、内部流转与案件状态汇总 |

页面接收显式 Props 和对应业务接口，不自行创建账号、文件或模型服务。聚合页只查看记录或导航回所属案件，办理动作统一由案件空间承载。

### 能力注册

`src/app/features.ts` 集中声明模块标签、图标、路由、所需能力及访问条件：

| 判断 | 含义 |
| --- | --- |
| `canView` | 是否可以查看该业务或历史 |
| `canStart` | 是否可以启动当前业务 |
| `canEdit` | 是否可以修改当前业务数据 |
| `FeatureAccess` | 统一返回 `visible`、`startable`、`editable` |

能力上下文从实际注入的 `DesktopAPI` 表面计算。Feature Registry 负责既有业务的启动 / 编辑语义；Panel Registry 驱动全局页面、案件页签、导航和组件装配。全局 / 单案分别声明注册列表，共用校验；声明接口不等于运行能力已经验收。

归档、结案、等待官方或等待后续的案件保留适用历史查看，不能借历史入口新增来源或重新启动任务。官方结论只锁其所属流程，后续明确可办理的新流程仍有当前业务入口；没有结论归属的旧记录保持整案锁定。浏览器预览也遵守只读边界。

### 历史与页面隔离

- `CaseHistory` 合并本地轮次和版本、Agent 全流程记录、Professional 来源和任务、内部流转记录。
- Agent 历史使用案件级接口，投影位于 `src/domain/history.ts`，不依赖 React、Electron 或文件系统。
- `professionalHistory(profileKey, caseId)` 按案件读取全部流程，不能用当前流程视图推断旧记录。
- 历史保留普通对话、分支、未完成任务、分析、未采用稿件、复核与定稿记录；账户级任务不混入单案历史。
- 指定历史目标缺失时显示错误，不回退当前记录；旧轮次、讨论和来源书签只读。
- 历史读取不触发当前办理打开动作，不创建转交会话；只读转交历史不触发远程写操作。
- 页面挂载身份绑定账号、桌面代际、案件、修订号、当前流程及历史目标；刷新、文件打开和事件回调不得污染新页面。

### 统一状态

复用 `LoadingState`、`ErrorState`、`ReadonlyState` 及相应空状态、重试入口：

- 首次加载、首次失败、已有数据刷新失败分别呈现。
- 刷新失败保留已读内容；无视图时不同时显示错误和加载态。
- 历史来源部分失败时保留成功来源，明确提示失败，不能伪装成“暂无历史”。
- 区分示例、本机保存、服务端读取、模型读取、运行中、产物生成、用户确认、服务端写入成功、结果待核验和只读。

实现与模板见 [模块接入指南](../development/module-guide.md)；历史可行性评估见 [旧面板注册方案](../design/panel-registry.md)。

## 2026-10-12：统一面板宿主

`src/app/panels.ts` 合并内置与自定义的编译期描述，注册器校验身份、路由、能力和历史入口。`src/modules/builtin.ts` 描述现有全部入口，`custom.ts` 为新增模块统一装配点。导航、页名和合法入口从同一注册表派生；面板 ID 不等于办理阶段。

`PanelHost` 统一访问判断、按需加载、局部加载失败与重试，按账号 / 案件 / 阶段代际与历史目标重建视图。按定义缓存已加载组件代码，重试时失效；不缓存组件实例或旧案件数据。数据租约在卸载时关闭；新面板默认只读且没有进入副作用。原生业务需要的 opened 初始化显式声明，切换页面不会停止后台任务。历史目标由历史适配器精确解析，未知入口明确提示不可用。

`CaseSpace` 管理案件级壳层、刷新与既有管理操作，`PageContent` 只选择全局或案件宿主。现有业务 UI 在 `src/modules/` 的兼容适配器中装配，新增组件无需在上述宿主中追加业务分发分支。
