# 开发与验收规范

> 当前技术参考；需求以 [需求索引](../../REQUIREMENTS.md) 及其模块细则为准，状态与待办见 [实施计划](../../EXEC_PLAN.md)。代码路径相对仓库根目录。

## 开发流程

1. 阅读需求、仓库规则、实施计划及相关源码，确认 Git 根、状态和已有 diff。
2. 明确本次接口、领域约束、兼容数据及影响范围。
3. 按领域规则、主进程适配、preload、UI 的顺序实现。
4. 按风险补充并发、账号切换、版本保护、恢复与失败路径测试。
5. 执行必要的定向回归；共享行为变化时运行 `npm test` 和 `npm run build`。
6. 构建已包含 `tsc --noEmit`；仅需类型检查时可单独运行，不重复记录为两轮独立验收。
7. 根据改动执行浏览器、桌面、安装、真实模型或授权隔离材料验证。
8. 检查相关 diff 与 `git diff --check`，在 `EXEC_PLAN.md` 更新当前证据和未完成项。
9. 代码复审、提交、推送、打包、发布与真实业务写入分别按本次授权执行。

普通文档整理不新增业务测试，不因排版变化重跑已通过且源码未变的全量检查。

## 复审与验收标准

### 区分三类结论

| 结论 | 能证明什么 | 不能替代什么 |
| --- | --- | --- |
| 开发自测通过 | 指定源码、命令及合成场景下的行为 | 独立代码复审或真实使用质量 |
| 独立代码复审通过 | 明确审查范围、问题清单及修复闭环 | 真机安装、真实模型和真实业务验收 |
| 文档核对完成 | 编号、链接、需求表述与已有证据一致 | 对全部源码正确性的审查 |

2026-09-26 的任务内复审属于历史证据，不能当作独立第三方验收；详见 [平台复审记录](../archive/platform.md#34-2026-09-26-复审口径历史记录)。

### 证据要求

| 验证维度 | 必须记录的证据 |
| --- | --- |
| 设计与需求 | 已确认范围、对应规则和未决项 |
| 自动化 | 源码范围、命令、结果与测试数据边界 |
| 独立代码复审 | 审查者、日期、源码或 diff 范围、发现、修复核验与残余风险 |
| 浏览器 | 路由、交互、视口、截图、错误来源及只读边界 |
| 桌面 GUI 与文件 | 当前构建、实际操作、落盘、退出恢复、迁移和账号切换结果 |
| 真实模型与 Word | 授权隔离材料、固定稿件版本、准确模板、内容和版式结果 |
| macOS 与 Windows | 对应平台、当前制品、安装或覆盖安装及启动结果 |
| 服务端读写 | 账号、案件、流程、授权范围、业务回读结果；不能只记录 HTTP 成功 |
| 官方递交 | 独立的官方递交证据；保存和内部转交不构成此项通过 |

未形成证据的项目标记“未验收”，不能以“已实现”或模型自述代替。
