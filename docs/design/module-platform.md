# 模块平台实施方案与复核

2026-10-12，基线 `6f31104` / 0.21.0。用户已授权完整规划、复核，再分阶段实现统一面板注册与宿主、统一数据管理、可替换适配器和模块接入模板，每阶段检查并本地提交。

## 交付目标

将新增内置模块的装配收敛到模块描述、组件及数据适配；现有答复、补正、撰写、独立审查、案件管理与内部流转继续使用相同业务规则。新模块可复用统一数据读取、受控写入、导航、访问判断、加载失败与重试机制。OpenCode 的自动兼容更新继续有效。

当前源码及安装包为 0.21.0。全部阶段通过后按新增功能升为 0.22.0，生成 macOS .app / .pkg 与 Windows .exe，保留已有制品。此次不推送、对外发布、覆盖用户安装或执行真实贝思兰德写入。

## 1. 面板注册与宿主

- 面板标识独立于业务 `Module` / 当前办理阶段 `WorkKind`，支持全局及案件内面板。内置描述包含唯一 ID、位置、路由、标题、顺序、能力要求、访问策略和显式生命周期。
- 注册表一次校验重复 ID / 路由、非法描述；导航、合法路由、标签及组件入口从同一表派生。既有 URL 和历史目标兼容；未知入口明确提示，不静默打开概览或当前稿件。
- `PanelHost` 统一处理权限 / 只读、按需加载、局部加载错误、重试和作用域变化后的组件重建。账号、代际、案件、流程、案件修订与历史目标共同确定生命周期。
- 将现有全局页面及案件页面迁入模块适配器；壳层只管布局与导航，不再列举业务组件分支。已有业务 Host 和领域状态机保留。
- 注册面板不授予任意 IPC 权限；只读模块没有写入操作，不继承“打开办理”副作用。既有需要初始化的业务入口显式声明。切换页面不停止后台任务，任务可从统一任务入口重新打开。
- 首期是随应用编译的内置模块；不运行下载的任意前端代码。内置模块变化仍通过新安装包交付，技能 / MCP 和 OpenCode 运行时继续沿各自已有入口更新。

## 2. 统一数据管理

统一身份、访问与持久化协调，不把所有数据混入同一可变对象，也不迁移用户数据库格式。

| 数据 | 唯一管理入口 | 边界 |
| --- | --- | --- |
| 案件领域记录与设置 | 主进程工作区仓储 | 沿用 CaseRecord、schema、摘要、原字节备份及未知字段保留；损坏拒绝覆盖 |
| 渲染层案件快照 | 统一工作区 Store | 接收有序主进程快照、复用保存队列、提供订阅与领域投影；不另存业务副本 |
| 模块数据 | 作用域绑定的数据接口 | 按账号 / 案件 / 阶段读取；只读接口不暴露写入；编辑通过当前作用域与主进程校验 |
| 材料及成果文件 | 现有受管文件入口 | 原件、版本、摘要、路径与覆盖保护保留 |
| 任务 / 对话 / 会话 | 现有领域 Host 与本机任务目录 | 与共享案件文件分离；保留恢复和引擎会话隔离 |
| 凭证 / 扩展秘密 | 系统 Vault | 不进入面板快照或共享目录 |

提取工作区持久化适配器，集中读取、校验、兼容转换及写入；DesktopService 保持流程协调和身份校验。渲染层采用可订阅 Store 与统一数据上下文，消除各层重复维护案件快照；乐观编辑和较晚返回的主进程状态继续由现有保存顺序规则处理。

## 3. 可替换适配器

- 将 Agent 执行合同独立于 OpenCode 实现文件，包含任务输入、输出、事件、取消及会话记录；通过有能力声明与版本检查的注册 / 选择入口构建执行器。生产仍使用实际验收的 OpenCode，测试用替代实现证明注入边界，不能声称已经支持另一个真实引擎。
- 贝思兰德客户端依赖提取为明确接口与工厂，覆盖案件读取、流程查询、文件及内部流转；业务 Host 不依赖具体客户端构造。真实服务端协议与业务核验规则保留。
- 工作区存储使用版本化接口，文件实现为默认适配器；使用受控测试适配器验证可替换性，正式应用继续保存当前格式。
- 替换发生在装配或后续任务创建时，不在已运行任务内改变其依赖。能力缺失、接口不兼容或未知适配器明确失败；不静默回退到含义不同的操作。

## 4. 模块接入模板

提供可实际生成的全局 / 案件只读模块模板、注册步骤、数据使用示例和测试模板；另提供需要后台写入或长任务时的契约 / 适配器接入说明。生成器校验名称和目标路径、不覆盖已有文件。新模块接入不改 App、PageContent、CaseSpace 的业务分发。

验证模板生成的模块能类型检查、构建和被宿主加载；验证生成器重复执行保护。模板说明数据范围、历史支持、能力声明、订阅清理、停止 / 恢复、迁移和验证责任。

| 阶段 | 内容 | 验收与提交条件 |
| --- | --- | --- |
| 1 | 现状核对、完整方案、风险复核和需求记录 | 对照实际入口与已有测试，逐项处理复核意见后提交文档 |
| 2 | 仓储、统一 Store 与模块数据入口 | 旧格式 / 未知字段 / 损坏保护、乐观保存、有序快照、账号和阶段 A→B→A、只读保护；相关回归与构建 |
| 3 | 注册器 / PanelHost，迁移全部内置页面 | 重复注册、能力不足、直达路由、历史 URL、懒加载 / 重试、只读无副作用；原生交互与三视口检查 |
| 4 | 引擎、外部业务、存储适配合同及装配 | 实际生产适配器和替代测试实现运行同类契约验证；取消 / 作用域 / 错误不改变业务语义 |
| 5 | 生成器、模块模板、接入文档 | 在隔离源码副本生成全局与案件模块，注册并编译 / 加载；不改宿主分支、重复生成保护 |

每阶段结束更新 EXEC_PLAN.md，检查相关 diff 并本地提交。阶段证据集中于 `evidence/module-platform/`；不建立第二套待办。Windows 实机、覆盖安装、真实供应商和真实案件业务质量仍分别报告，不能由本机合成验证替代。

## 实施前复核

在方案形成后按反例重新检查以下事项，结论作为实施约束：

| 复核问题 | 对策 / 通过标准 |
| --- | --- |
| 注册一个面板是否被误认为新办理阶段？ | 面板 ID 与 WorkKind 分离；只改变导航，不写 current |
| 只读面板是否执行 opened、创建任务或转交会话？ | 默认无进入副作用；旧业务显式适配；合成 spy 和原生任务数验证 |
| 未知 / 不可见路由是否落到别的有效页面？ | 宿主返回不可用结果；导航与直达路由共用访问策略 |
| 历史链接是否读取当前稿？ | 保留完整目标字段；不存在的目标必须明确失败，不能回退当前 |
| 延迟读取 / 保存是否跨账号、阶段或返回旧页面后生效？ | 沿用 generation / revision / snapshotVersion；Store 与模块数据接口绑定作用域 |
| 统一 Store 是否将业务缓存与凭证混用？ | 只接收 DesktopState 公共合同；不合并秘密、共享文件和本机任务存储 |
| 仓储提取是否损坏旧记录或丢未知字段？ | 原有迁移回归保留；真实临时文件核验原字节、hash 与写入保护 |
| 适配器只是换了类型名，生产仍绕过工厂？ | 检查实际装配点；替代实现经同一工厂 / 注册入口触发完整输入输出与取消合同 |
| 模块卸载是否中止后台任务或删除历史？ | 仅清理前端订阅；任务归业务 Host；切换后重新打开可查看 |
| 模板只有文档没有可运行接入？ | 实际生成两个位置的模块，在隔离副本注册、构建和加载 |
| 技术改造是否扩大真实业务授权？ | 仅合成材料和独立配置；不使用真实凭证 / 案件，不做生产内部转交 |

复核结论：按上述边界可渐进落地。原“仅评估，未授权实施”的限制已被本次明确授权更新；历史记录原文保留。数据格式迁移、第三方前端运行时插件及第二个真实 Agent 引擎不作为本轮已经具备的能力。是否满足快速接入，以模板模块的实际验证为准。
