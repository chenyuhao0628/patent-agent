## 待实施设计

2026-09-29 代码核对结论：**可以在现有架构上实现，工程复杂度中等，主要风险在旧路由、办理权限和异步身份的兼容迁移。** 不需要为首期更换 Electron / React、引入新的应用框架或改变案件存储格式。本方案为待实施设计建议；用户当前授权是评估，不代表已确认或完成下列改造。

#### 最小可行设计

采用**内置面板的编译期注册**。每个面板提供一个描述及自己的界面 / 适配器，宿主从注册表派生导航、合法路由、标题、可访问性及渲染入口。面板标识与案件 `WorkKind`、业务 `Module` 分开：新增统计或材料检查面板不应自动新增案件办理阶段。

建议描述包含：稳定 `id`、全局工作空间或案件内的 `placement`、路由 / 旧入口别名、名称、图标、排序、所需能力、访问策略、组件加载器、专用上下文适配器。全局面板取得所需汇总数据；案件面板取得对应裁剪视图、当前或确切历史目标，以及账号、桌面代际、案件、修订号和流程身份。写入使用已有业务 API，不直接修改底层案件库。

统一 `PanelHost` 负责入口核验、身份变化后的视图重建、加载 / 错误 / 只读状态及标准布局插槽。直接输入路由必须与导航点击执行同一访问策略；未知、缺失或无权访问的目标明确反馈，不能静默替换为当前稿件。布局复用标题、工具栏、内容区与底部操作区，正文宽度和滚动可按面板声明，不强制所有业务套同一种表单。

注册元数据与纯访问判断保持不依赖 JSX 和副作用，兼容现有 Node 类型剥离测试方式；大面板按实际打开时加载，并提供局部加载失败反馈。宿主切换只负责清理界面订阅和拒绝迟到响应，不能默认停止后台任务或触发「开始办理」。现有 `CaseSpace` 的 `opened` 行为应由兼容适配器按既有业务语义承接，新只读面板不得自动继承办理副作用。

#### 接入边界与预期收益

| 后续需求 | 完成注册机制后的正常接入工作 | 不能承诺的内容 |
| --- | --- | --- |
| 复用现有数据的展示 / 检查面板 | 新增组件、专用上下文适配器与一条注册；不再改多处分发分支 | 不会自动生成业务界面或算法 |
| 新后台服务能力 | 上述面板接入，加公开契约、preload、运行时解析、作用域策略、主进程 handler 和实际服务实现 | 不会因为前端声明了能力就具备后台权限 |
| 新模型长任务或文件成果 | 在前两项上补任务摘要、事件、停止 / 恢复及精确成果 / 历史适配，按需接入任务中心 | 不把任务与成果兼容简化成只写面板配置 |
| Skill / MCP 扩展 | 沿用现有工具与技能入口，供受限任务使用 | 不自动安装或生成前端面板 |

首期不包含第三方任意前端代码、免重编译的外部面板安装、插件市场或跨版本插件沙箱。这些是另一层加载与授权机制；内置面板变更仍需构建和发布新版程序。前端窄类型和导航可见性不是安全沙箱，主进程仍是最终授权边界。

#### 推进顺序与验收门槛

建议先建立注册表和宿主，用一个只读全局面板、一个只读案件面板验证接入链路；保留所有现有 URL 与历史目标兼容。随后逐个迁移撰写、审查、答复和流转的装配，既有业务 Host、文件身份与状态机保持原样；新增长任务时再扩展任务 / 成果适配，不为抽象统一而重写全部业务。

实施验收应至少证明：新增试验面板只需组件、适配器和注册，不再修改 `App`、`PageContent`、`CaseSpace` 的业务分发分支；重复 ID / 路由在开发检查中失败；能力缺失和直达路由都被正确拦截；旧书签、指定历史版本和缺失来源行为保持；账号 / 案件 / 流程 A→B→A 的迟到响应无效；新只读面板不启动任务、不创建转交会话；移除或禁用面板不删除历史成果；正在运行的任务切换面板后仍可恢复查看。

还须实际验证局部加载失败、订阅清理、后台任务与文件落盘，以及 1280×800、1440×900、1920×1080 布局和双平台桌面行为。仅本次现有回归通过，不能替代这些新机制的实现和 GUI 验收。评估过程和当前验证证据见 `EXEC_PLAN.md`。
