# UI 规范与设计标准

规范版本：UI 1.0，制定于 2026-10-12。覆盖独立 macOS / Windows 专利工作台，包括全局页面、单案业务、设置、弹窗和模块扩展。用户确认的目标是**界面对齐、各类页面统一**；下列尺寸、色值和组件分工是本次据现有产品制定的工程基准，不是用户逐项指定的数值。

本文件规定目标设计。现有代码与规范之间的差距见 [页面统一方案](ui-unification-plan.md)，实际完成状态只见 [EXEC_PLAN.md](../../EXEC_PLAN.md)。业务需求仍由 [REQUIREMENTS.md](../../REQUIREMENTS.md) 及其分册管理；视觉规范不能改变保存、定稿、流程、权限或会话隔离规则。

## 1. 适用原则

- 面向日常专利办理，优先清晰阅读、快速定位、稳定操作和准确状态；沿用现有浅色工作台与克制的紫色主操作，不新增营销首页、大标题或装饰插画。
- 同类元素使用同一组件、尺寸和行为。表格、长文阅读、对话及表单可以有不同工作区结构，页面外框、文字层级、动作和状态保持一致。
- 全案与单案分别注册。全案面向当前账号的汇总，单案面向明确的案件和办理阶段；进入列表或只读历史不创建模型任务、转交方案或新的业务状态。
- “统一”优先统一组件职责、布局约束、状态含义和资源加载，随后迁移视觉参数；不通过覆盖所有 CSS 来掩盖业务页面的不同需要。
- 成功与完成必须有真实依据。读到文件、模型退出、保存到本机、保存到贝思兰德、内部转交、官方递交分别显示。
- 新模块和本次以后实质改造的区域按本规范建设。旧区域在对应迁移阶段处理；不得仅因存在旧例外而继续复制旧写法，也不在小修复里无范围地重做整页。

## 2. 基础参数

数值均为 CSS 像素，以默认根字号 16px 为换算基准。文字使用 rem；窗口变化只改变分栏、换行和间距档位，不能使用 vw 缩放文字或整体 transform 缩放页面。允许系统缩放及用户显式阅读字号设置。

### 2.1 尺寸与间距

| 参数 | 标准值 | 使用规则 |
| --- | --- | --- |
| 间距刻度 | 4、8、12、16、20、24、32、48 | 默认只从刻度取值；1px 边框和图标光学校正除外 |
| 页面内边距 | 宽度 ≥900 时 24；<900 时 16 | 同一窗口内所有全局页面一致，单案外框也沿用同一左、右起线 |
| 标题区到工具栏 / 正文 | 24 | 有说明时属于标题区；无说明时不留空说明占位 |
| 工具栏到结果区 | 16 | 表格、任务、流转、审查与案件状态一致 |
| 分区间距 / 分栏间距 | 24 | 同组内部使用 12 或 16，不为每页另定 18、22、30 等近似值 |
| 主导航宽度 | 宽度 ≥1152 时 224；900–1151 时 192；<900 时 64 | 所有页面共享壳层，不由单个页面改变侧栏宽度 |
| 顶栏高度 | 56 | 顶栏与侧栏稳定，不随内容页或宽屏放大 |
| 表单 / 工具控件 | 默认高 36；紧凑行高 32 | 同行按钮、搜索、下拉选框使用同一档；触控粗指针目标至少 44 |
| 图标按钮 | 默认 36×36；紧凑 32×32 | 固定点击范围，图标本身不变成点击范围；粗指针采用 44×44 |
| 表格表头 / 数据行 | 表头最小 36；一行数据最小 44；双行最小 64 | 最小高度，不裁切换行内容；同一表格由同一列定义控制表头与数据 |
| 圆角 | 控件 6；标签 4；记录容器 / 弹窗 8 | 页面分区使用留白和分隔线；仅重复记录、弹窗、真实编辑 / 预览工具保留外框 |
| 边框 | 1 | 聚焦环 2；选中页签底边 2；不以加粗边框挤动布局 |
| 图标 | 控件 16；导航 18；强调状态 20 | 使用既有 lucide-react，strokeWidth=1.75，禁止用表情或手绘图标混排 |
| 动效 | 120–180ms | 仅颜色、透明度等轻量反馈；减少动效设置下关闭非必要动画，不人为延迟加载完成 |

### 2.2 字体与信息层级

使用现有本机字体栈：`Inter, -apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`；Inter 未安装时直接使用系统字体，不为操作界面联网下载字体。Word 模板、正文公式和文档字号独立，不受 UI token 批量覆盖。

| 角色 | 字号 / 行高 | 字重与边界 |
| --- | --- | --- |
| 全局页面标题 | 24 / 32 | 600；一页一个 H1 |
| 单案身份标题 | 20 / 28 | 600；作为单案 H1；业务区域从 H2 开始 |
| 业务分区标题 | 18 / 26 | 600；不随宽屏升为 26、30px |
| 列表记录标题 / 分组标题 | 15 / 22 | 600；多行标题仍保持操作列对齐 |
| 正文与控件 | 14 / 22 | 400；紧凑表格、次级按钮可用 13 / 20 |
| 标签、时间、辅助信息 | 12 / 18 | 400–500；关键状态、期限、错误不使用 9–10px 小字 |
| 长文编辑 / 阅读 | 默认 15 / 27 | 可按文档功能显式调整；不把文档样式扩散到导航、按钮或列表 |
| 数字与时间 | 对应角色字号 | `font-variant-numeric: tabular-nums`；数字列右对齐，正文列左对齐 |

所有 UI 文本 `letter-spacing: 0`。优先换行、增加行高或重新分栏，不通过缩小长标题字号解决空间不足。多行正文不强制单行省略；案件 / 文件列表标题可省略，但必须能通过聚焦提示、详情或打开记录取得完整内容。

### 2.3 颜色与状态

| 语义 | 前景 / 背景 | 用途 |
| --- | --- | --- |
| 应用底色 / 内容 | `#f6f7f9` / `#ffffff` | 中性底色，内容区为白色；不对整个页面铺强调色 |
| 正文 | `#232631` | 案件、稿件、字段值和核心状态 |
| 次级文字 | `#596273` | 描述、来源和次级字段 |
| 辅助文字 | `#697285` | 时间、摘要、提示；仍须可读 |
| 普通分隔 / 可交互边界 | `#e3e7ee` / `#818b9c` | 浅线用于分区；必须靠边框识别的输入框用后者，不用浅分隔线承担全部识别 |
| 主操作 / 选中 | 主按钮 `#ffffff` / `#625de8`；选中文字 `#534ed3` / `#f0efff` | 主操作、选中入口；hover 用 `#534ed3`，禁止整页紫色卡片 |
| 完成 / 成功 | `#277451` / `#edf7f0` | 有证据的完成；配文字或图标 |
| 待核对 / 警告 | `#895b15` / `#fff8e8` | 未确认、部分失败、尚有缺项；不能当作成功 |
| 错误 / 危险 | `#b42318` / `#fff0ee` | 失败、删除与不可逆影响提示 |
| 运行 / 信息 | `#245ca6` / `#eef5ff` | 正在办理、读取或有来源的信息 |
| 中性 / 只读 | `#596273` / `#f1f3f6` | 停止、历史、未执行、只读，不降低到无法读取的透明度 |

目标为普通文字对比度 ≥4.5:1，大字号文字和必要非文本控件边界 ≥3:1。按上述准确色值计算：辅助文字 / 白色为 4.83:1，辅助文字 / 应用底色为 4.51:1，主按钮为 4.94:1，选中入口为 5.44:1；成功、警告、错误和信息色组均大于 5:1。实际叠加透明度、hover、disabled、选中背景后仍需重新检查，这些数值不代表现有页面已全部通过。

色彩不能独自表达状态，至少同时提供文字或形状。官方驳回是业务结论，不当作网络故障；任务完成不意味着案件结案。

焦点使用 2px `#625de8` 外环并留 2px 间隔，在有色背景上核对可见性。禁用控件使用明确的浅底、次级文字与原因，不对整个含正文的区域统一降低 opacity。hover 不改变字号、边框占位或控件宽度。

## 3. 页面外框与对齐

标准框架为：主导航 → 顶栏 → 页面标题与动作 → 可选筛选 / 状态栏 → 内容区 → 可选保存动作。嵌入 PanelHost 的面板只能提供自己负责的层级，不能再套一层侧栏、重复标题或重复全页 padding。

```text
全局页：AppShell / 顶栏
         页面标题                 本页主动作
         搜索、筛选               结果数、次级动作
         列表或记录区             固定的行操作列

单案页：AppShell / 顶栏
         案件身份                 刷新本案、案件管理
         单案导航（仅当前业务入口可办理）
         当前业务标题             本步骤动作
         材料、正文、依据等业务工作区
```

### 3.1 必须保持的起线

| 对齐对象 | 规则 | 可测条件 |
| --- | --- | --- |
| 全局标题、工具栏、结果区 | 共享同一内容左起线；同宽度页面不单独居中 | 相同视口相对 `main` 的 left 差 ≤1px |
| 标题和右侧动作 | 操作区顶边对齐标题区，使用稳定高度；说明换行只增加标题区高度 | 操作不压标题、不被推到未知位置，right 差 ≤1px |
| 单案身份、页签、业务正文 | 外框左、右起线一致；内部阅读纸张允许额外留白 | 切页前后案件标题和页签坐标差 ≤1px |
| 搜索、筛选、刷新 | 同一 toolbar 使用相同高度和垂直中心 | 高度差 ≤1px；空间不足整组换行，列间距为 8 / 12 |
| 表格与列表操作 | 表头、数据复用列定义；操作区域宽度由本组最长操作组合决定 | 同一列表按钮起线差 ≤1px；换行后整列转下一行 |
| 表单 | 标签在控件上方，label 与 field 左对齐；同排控件顶部对齐 | 不同提示高度不拉歪同排输入；错误在所属字段下方 |
| 状态、图标、数字 | 状态正文基线一致，图标固定框与文本中心对齐 | 图标尺寸不因文字 / loading 变化；不用空格拼列 |

页面内容框始终使用可用宽度。案件库等表格不设居中窄列；普通表单可在统一左起线内限制为 800px；长文纸张可在业务栏内设阅读宽度，禁止把整个页面标题一起移动。页面宽度不由某一条长案名撑开，布局子项统一 `min-width: 0`。

### 3.2 响应式与滚动

- 主要验收视口：1280×800、1440×900、1920×1080；另测 1440×812 的可用内容高度，代表标题栏及系统栏占用。700×800 和 390×844 用于防截断压力检查，不代表交付移动版。
- 列表页面只让主内容纵向滚动；宽表格可有内部横向滚动，不能藏掉期限、状态或文件身份等关键列来制造“无溢出”。
- 对话具有明确高度，输入区和停止操作保持可达，消息区独立滚动。撰写保留正文阅读高度及阶段确认区，左侧输入与材料共用一个滚动区；允许必要的整页滚动，不要求所有内容塞进首屏。
- 同一侧栏或内容栏避免再套多个同方向滚动容器。设置 `min-height: 0`、`overscroll-behavior: contain`，滚动条与文本之间保留空间。
- 保留全局滚动条槽位，切页出现滚动条不横向挪动标题与动作。
- 窄屏优先将次级栏放到正文后、工具栏按组换行、操作列整体下移。表单和弹窗在 200% 缩放时仍可滚动到全部操作，不裁切内容或遮挡焦点。

## 4. 组件标准

| 组件 | 统一行为与布局 | 实现约束 |
| --- | --- | --- |
| 页面标题 | 一个标题，必要的范围 / 当前状态，右侧一个主动作组 | 标题取当前注册项 / 业务定义；不在每页重复写帮助长段落 |
| 按钮 | 同行同高；主要、次要、危险三种视觉层级 | 保存、生成、转交保留明确动词；图标工具使用 lucide、可聚焦提示和 aria-label |
| 主操作 | 同一决策区域一个主动作 | 撰写“继续未完成任务”和“生成新版本”有明确优先；不同独立表单可各有主动作 |
| 工具栏 | 左侧搜索 / 筛选，右侧结果数 / 操作，空间不足按组折行 | 禁止浮动定位和不断追加 margin 推齐；搜索清空恢复当前集合 |
| 页签 | 切换内容的导航；当前项有底边和文字状态 | 支持键盘、可见焦点；条件隐藏不能创造第二个当前办理阶段 |
| 分段选择 | 同一页面的少量互斥模式，如待审 / 记录、编辑 / 预览 | 与导航页签区分；二元值使用 checkbox / switch，选项多时使用 select |
| 列表行 | 标题、身份 / 元信息、状态、动作四个稳定区域 | 案件、任务、稿件保留各自数据身份，不能为了统一外观改成一种业务记录 |
| 表格 | 共用列定义，表头和行精确对齐；稳定排序与选择 | 点击行、复选框、行内按钮行为分别处理；键盘可操作 |
| 状态标签 | 语义色 + 文字，默认字号 12 | 同一语义跨页同名同色；任务状态与案件结论不能互相映射 |
| 表单字段 | 持续可见 label、输入、必要提示 / 错误 | placeholder 不代替 label；保存失败保留输入，验证错误关联 aria-describedby |
| 折叠详情 | 摘要行高至少 36，末端同一 ChevronRight 旋转 | 默认折叠证据与日志；错误不藏在完全看不到的详情内 |
| 弹窗 | 建议宽 480 / 720 / 960，边缘留 24；窄屏留 16 | 标题与关闭按钮、正文滚动区、动作区三层；按内容采用最小适用尺寸 |
| 弹窗焦点 | 打开后焦点在弹窗，关闭后回触发处；支持 Escape | 有未保存修改时走既有保护；危险确认默认聚焦取消，背景不可操作 |
| 文件行 | 文件名、角色、版本 / 来源、状态、动作分别对齐 | 文件名可换行，FileNo / 哈希详情可展开；不凭同名合并身份 |
| 流程节点 | 编号 / 状态符号、节点名、证据时间、详情 | 节点文字可换行，状态不能只靠颜色；未执行、未知、可选、已完成分开 |
| 文档工具 | 格式、预览、下载等采用图标或图标加文字 | 编辑框 / 纸张是允许有外框的工具；不能修改用户指定 Word 模板来配合 UI |

保留现有 `Primitives.tsx` 中的 `Modal`、`Empty`、`LoadingState`、`ErrorState`、`ReadonlyState`，先完善再复用。拟新增 `PageHeader`、`FilterToolbar`、`ActionGroup`、`StatusBadge`、`FormField` 等组件；这些名称是接入方案，当前不能直接假设已有导出。表格、对话、专业工作台各自保留领域组件，不建设一个涵盖全部业务的巨型“通用页面”。

## 5. 状态与交互一致性

| 状态 | 应显示与允许操作 | 禁止行为 |
| --- | --- | --- |
| 首次加载 | 保留页名和范围；内容区显示正在读取或与最终内容对应的占位 | 空白页、整个壳层闪烁、为动画强制等待 |
| 空数据 / 无搜索结果 | 区分无记录与筛选无结果，给出清空筛选或已有合法动作 | 将读取失败显示成暂无内容 |
| 刷新中 | 旧数据保持可见，标明刷新；影响范围内避免重复请求 | 一刷新就清空正文、全局强制重挂载或自动启动任务 |
| 刷新失败 | 保留旧数据、显示上次成功状态与重试入口 | 把旧值标成刚获取成功，覆盖用户正在编辑的字段 |
| 未保存 / 保存中 / 已保存 | 反馈靠近相关编辑和保存动作，区分本机与远端目标 | 在实际写入前显示已保存；保存失败清空输入 |
| 保存或转交结果不明 | 显示需要回读核对，提供明确恢复操作 | 自动重发、用通用成功提示覆盖不确定状态 |
| 只读 / 无权限 | 保留可看内容和原因，明确哪些操作不可用 | 仅灰掉按钮而不解释；靠 UI 禁用替代主进程校验 |
| 长任务 | 显示当前动作、耗时、最近活动、停止与所属案件 | 切换页面就停止；把模型完成当作定稿或提交 |
| 停止 / 失败 / 可续办 | 已输出内容和已保存产物保留；明确继续或新分支重试 | 自动采用旧稿、在后台无声重放副作用 |
| 部分成功 | 分项标出成功、失败与未执行 | 一条绿色横幅覆盖全部失败项 |
| 历史目标缺失 | 显示目标不存在或读取失败，并提供回历史入口 | 自动显示当前稿件作为指定历史结果 |

业务保护继续有效：普通补充消息入队；编辑历史消息重发才先停止当前任务；审查可选且不新增定稿门槛；材料勾选范围不能因统一组件而扩大；账号、案件、阶段、分支、版本变化后拒绝迟到回执。

文案只说明当前数据、动作后果或必须判断的风险。通用教程进入使用说明 / 帮助，技术实现细节进入诊断，不在日常页面重复宣传功能。全局名称以注册项为准；“审查队列”“稿件审查”“独立复核”分别表示汇总入口、单案能力和可选步骤，不强行改成同一业务词。

## 6. 样式与模块工程标准

### 6.1 所有权

| 层级 | 所有者 | 规则 |
| --- | --- | --- |
| 设计 token | 拟建 `src/ui/tokens.css` | 颜色、字号、间距、尺寸、层级的唯一变量来源；该文件尚未实施 |
| 全局壳层与基础重置 | 主入口及壳层样式 | 侧栏、顶栏、焦点、全局滚动条从启动即存在，不由某个案件页注入 |
| 共享控件 | 控件自己的组件 / CSS | 组件直接引入样式；独立使用也完整，不能借另一个业务组件间接加载 |
| 页面模块 | 注册组件及其 CSS | `AgentTasks`、`LocalWorkflow` 等只定义自己的布局，不写其他页面选择器 |
| 文档内容 | 预览 / 导出子系统 | 公式、Word 内容、图形与 UI 命名空间隔离；不修改模板字号来统一导航 |

每个模块依赖的资源必须可从其入口完整追溯。首次直达、刷新、从任意页面返回的计算样式相同；不能要求先打开本案对话才让全局页显示正常。为复用样式不能反向 import 整个案件工作台。

### 6.2 迁移与加载

首批变量映射约定如下；文件与组件尚待 U1 / U2 实施，不能在未定义时直接删除原变量：

| 变量 | 目标值 / 来源 | 兼容入口 |
| --- | --- | --- |
| `--ui-color-accent` / `--ui-color-accent-soft` | `#625de8` / `#f0efff` | `--accent` / `--soft` |
| `--ui-color-accent-strong` | `#534ed3` | 主按钮 hover 和浅色选中背景上的文字 |
| `--ui-color-text` / `--ui-color-muted` / `--ui-color-divider` | `#232631` / `#697285` / `#e3e7ee` | `--ink` / `--muted` / `--line` |
| `--ui-space-1` 至 `--ui-space-6` | 4 / 8 / 12 / 16 / 20 / 24px | 原页面间距逐批迁移 |
| `--ui-space-8` / `--ui-space-12` | 32 / 48px | 分区或大留白 |
| `--ui-page-padding` | 宽度 ≥900 时 24px，<900 时 16px | 全局 / 单案外框共用 |
| `--ui-control-height` / `--ui-control-height-compact` | 36 / 32px | 按钮、输入、搜索和 select |
| `--ui-radius-control` / `--ui-radius-surface` | 6 / 8px | 可交互控件 / 记录与弹窗 |
| `--ui-font-body` / `--ui-font-caption` / `--ui-font-page-title` | 0.875 / 0.75 / 1.5rem | 与第 2 节文字角色一致 |

- 目标变量采用 `--ui-*` 命名；迁移期将 `--accent`、`--ink`、`--muted`、`--line`、`--soft` 映射到统一变量，避免两套变量长期各自变化。
- 先创建 token 与基础组件，再逐类替换并删除旧规则。不在文件末尾不停追加覆盖，也不以选择器重复和 `!important` 争夺优先级；旧例外逐条在迁移 diff 中说明去留。
- 不盲目把新样式放入 `@layer`：现有未分层 CSS 会优先于分层样式。若引入层级，须在一次受控变更中明确未分层规则如何迁移，并检查构建后的实际顺序。
- CSS 使用模块前缀，避免 `.active`、`header`、`small` 等无范围业务规则污染其他页。第三方 KaTeX 样式维持自己的边界。
- 框架继续使用现有 React、CSS 和 lucide；本规范不要求引入新组件库、CSS 框架、联网字体或运行时主题依赖。
- token、组件复用和视觉切换不能新增模型请求、文件写入或全案同步；不通过提高轮询频率制造“更实时”的错觉。
- 宿主卸载只清理 UI 订阅；后台任务和会话由原 Host 管理。保存继续走现有队列、作用域 guard 和主进程仓储。

## 7. 可访问性与可检验质量

- 所有操作可通过键盘达到，有清晰焦点；图标按钮必须有可访问名称和鼠标 / 键盘均可触达的提示。tab / radio / checkbox 使用正确语义与键盘习惯，不只靠 div 点击。
- 表格有列标题和排序状态；状态更新使用合适的 status / alert，流式长文本不逐字广播全部正文。
- 弹窗有可访问标题、焦点管理、Escape 和关闭按钮；层级统一规划为内容 0、sticky 10、菜单 20、浮层 30、提示 40，原生 dialog 使用 top layer，不以任意 9999 解决互相遮挡。
- 长案名、FileNo、英文模型名、公式与错误信息都要有换行 / 省略后完整查看策略，按钮不能被文字撑大、遮住正文或溢出父容器。
- 普通页面截图和交互需使用合成案件及隔离账号；不得把真实材料、凭证或完整私有路径放入公开验收附件。
