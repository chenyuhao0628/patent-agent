# UI 对齐与页面统一实施方案

2026-10-12，核对基线 `30bbe27` / 0.22.0。用户已要求完整规划并设定 UI 规范，要求对齐与各类页面统一。规范见 [UI 1.0](ui-standards.md)。本文件保存代码盘点、目标映射、实施顺序和复核；阶段实际状态只维护于 [EXEC_PLAN.md](../../EXEC_PLAN.md)。

本轮继续修复已复现的“内部流转 / 工作任务”样式缺失。其余页面的统一列为完整迁移方案，不因文档完成而声明 UI 已全部改造。方案不调整案件状态机、材料身份、正文、Word 模板、模型配置或服务端提交语义。

## 2. 页面覆盖清单

每个入口按所在作用域验收。当前注册包含 7 个可见全局入口、2 个隐藏兼容入口和 10 个单案注册项；单案实际可见项依阶段与权限变化，不能以一个案件的可见数量代表所有入口。

### 2.1 全局工作区

| 入口 | 现有组件 / 记录类型 | 统一重点 | 关键检查 |
| --- | --- | --- | --- |
| `#/library` 案件库 | Library；案件摘要 | 页面起线、统计 / 筛选 / 表格间距、列定义、批量动作 | 长案名、多列、排序、拖列、选择、归档权限与打开目标 |
| `#/official` 等待官方 | Library 的官方等待范围 | 复用同一列表框架，保留官方等待状态来源 | 回执不当作结案；授权 / 驳回之后的归属展示 |
| `#/tasks` 工作任务 | AgentTasks；答复 / 讨论 / 专业任务 | 标题和状态、固定操作列、失败信息换行、任务类型 | 多任务、失败 / 停止 / 完成，按 runId 回到确切记录 |
| `#/review` 审查队列 | ReviewQueue；稿件与审查记录 | 页面名称、分段选择、搜索及报告弹窗 | 待审与记录计数不同；版本 / 来源保持明确 |
| `#/transfer` 内部流转 | LocalWorkflow；当前办理及节点 | 标题、过滤器、记录头、节点网格与操作起线 | 全案汇总不变成单案转交表单；完整节点证据保留 |
| `#/status` 案件状态 | CaseOutcomeCenter；官方结论 | 搜索、状态标签、列表与错误反馈 | 未判读、未见结果、授权、驳回不混淆 |
| `#/settings` 设置 | SettingsPage | 共享外框、分类导航、表单 / 长表格宽度与保存反馈 | 以下八类分别首开；错误不丢输入 |
| `#/reply`、`#/write` | 隐藏兼容入口的 Library 范围视图 | 复用新列表框架，保持旧链接 | 无新增可同时办理的全局业务；打开正确案件和阶段 |

### 2.2 单案工作区

| 注册项 | 现有主体 | 标准布局及验收 |
| --- | --- | --- |
| overview 概览 | OverviewPanel、CaseMetadata | 案件身份 / 当前办理 / 事实区分层，共用外框；流程和结论不能重复矛盾 |
| materials 材料 | CurrentCase、MaterialsView | 材料行对齐，当前通知与原始申请身份明确；导入 / 勾选 / 预览各自有状态 |
| discussion 本案对话 | CurrentCase、AgentWorkbench | 明确消息滚动区、输入区、停止和分支；全局切换不停止任务 |
| reply 答复或补正 | ReplyPanel、AgentWorkbench | 同一对话控件，材料核对 / 策略 / 草稿 / 复核 / 定稿保持原业务条件 |
| write 撰写 | ProfessionalWork、WritingWorkbench | 输入 / 材料一栏，正文与确认另一栏；起点、回退和旧版本显式采用保留 |
| review 稿件审查 | ProfessionalWork、ReviewWorkbench | 来源版本、可选审查、正文与问题 / 报告；主讨论不进入独立上下文 |
| submit 提交 | InternalTransfer | 材料 / 业务表单 / 接收人与结果三段，统一文件行及状态；保存、回读和转交分开 |
| history 办理历史 | CaseHistory | 稳定记录行、按确切目标展开；缺失目标不回退当前稿 |
| outputs 成果 | CurrentCase、ProfessionalArtifacts、TransferWorkbench | 文件、版本、来源与动作对齐；已保存、已采用、已定稿不混用 |
| flow 贝思兰德流程 | RemoteFlow | 当前节点、办理人、官方递交 / 回执 / 结论分层；只读查询与本机进度区分 |

单案导航保持一个当前业务。提交页与流程页的顺序已登记为 D1，在单案迁移阶段处理并回归直达 / 历史路由，不把它隐含在样式补丁里。

## 3. 组件与样式接入规划

| 交付 | 复用与改造方式 | 所有权 |
| --- | --- | --- |
| `src/ui/tokens.css`（待建） | 集中 UI 1.0 色值、文字和布局变量；旧变量暂映射到新值 | 根入口静态加载，仅一次 |
| `PageHeader` / `FilterToolbar`（待建） | 全局页面标题和工具栏共用骨架；单案业务标题保留级别参数 | 共享 UI，不能读取业务数据或主动同步 |
| `ActionGroup` / `StatusBadge`（待建） | 操作顺序与状态语义一致；传递真实动作与状态 | 不在组件中猜测转交权限或服务器结果 |
| `FormField`（待建） | label、hint、error、aria 关系和尺寸统一 | 模型、目录、账号仍各自管理业务校验 |
| 既有 Primitives | 完善标题关联、焦点恢复、重试、空状态类型 | 保持原导出兼容，分批迁移调用方 |
| `CaseSpace` 与各业务主体 | 同一身份头和页签外框；组件内只负责所属区域 | 全案 / 单案共用设计 token，不共用无范围数据副本 |
| 列表行与文件行 | 抽共用排版和动作区；保留各自领域字段 | task / case / review / transfer 类型不混并 |
| CSS 清理 | 同阶段替换选择器与删除旧覆盖，直接 import 组件样式 | 无新增框架依赖；不更改 KaTeX 或 Word 正文样式 |

先让依赖闭合，再形成 token 与共用组件，最后按页面族迁移。不能先改全局 `.button-row`、`h1` 或 `small` 后要求所有页面被动适配；迁移时旧调用方应保持原行为。

## 4. 分阶段路线

本表是实施依赖和验收约定，不重复维护进度。当前 UI 故障修复属于 U0；U1–U6 为完整统一改造计划，不在本轮规划完成时标为完成。

| 阶段 | 主要改动 | 验收后才可提交 / 进入下一阶段 |
| --- | --- | --- |
| U0 独立加载 | 修复任务、流转样式归属；共享壳层规则回入口；构建资产回归 | 在旧版本复现、修复后冷 / 暖 / 刷新一致；有内容页面、筛选和任务定位无错误 |
| U1 基础参数与外框 | token、侧栏 / 顶栏 / 页面尺寸、字体层级、默认对比度；旧变量映射 | 三桌面视口的标题 / 工具栏起线、旧单案标题不跳动；不新增数据请求 |
| U2 通用控件与反馈 | PageHeader、工具栏、动作组、表单字段、状态标签；完善 Modal / 通用状态 | 空 / 错误 / 刷新失败 / 只读分开；键盘、焦点、缩放、长文字及共享样式独立加载 |
| U3 全局页面 | 案件库、等待官方、工作任务、审查队列、内部流转、案件状态 | 所有全局路由首开；同宽度左起线、按钮列、筛选控件对齐；计数和记录身份不变 |
| U4 单案页面 | 身份头、页签、概览、材料、答复 / 补正、撰写、审查、成果、历史、流程、提交 | 三种当前业务各一案；正文滚动、输入 / 确认可达；D1 顺序、旧 URL、只读历史、保存与停止回归 |
| U5 设置与弹窗 | 八类设置、文件 / 稿件 / 版本 / 确认弹窗 | 当前账号范围、连接测试取消、保存失败保留输入、目录预览和只读凭证；无未授权网络 / 写入 |
| U6 清理与交付 | 删除被替代样式、补接入模板、完整回归、安装包与文档更新 | 首开矩阵、性能对照、三桌面视口、原生 GUI、双平台包内核对；平台实机限制如实记录 |

每阶段先读目标页面及当前需求，再实现、复核相关 diff、执行风险匹配的检查，并按现有授权本地提交。不能因统一 UI 顺带修复与本阶段无关的目录命名或同步缓存；D2–D4 继续独立管理。后续整套统一不应复用 U0 修复版号，实施交付时按实际变更语义升版。

## 5. 复核后的约束

| 反例 / 风险 | 方案处理 | 复核结论 |
| --- | --- | --- |
| 共用 UI 是否把全案数据带入单案模型？ | 只共享样式与控件，沿用 ModuleData 作用域及原 Host | 保留边界，不创建跨案模型上下文 |
| 所有页面用一种卡片是否丢业务重点？ | 列表、表格、对话、阅读、表单采用各自布局；外框与组件规则共用 | 不采用整页卡片套卡片或万能工作台 |
| 调整间距是否改变刷新、保存链路？ | 无新 effect、轮询和读写；保存队列 / IPC / Host 不移动到 UI 组件 | 相关回归与调用次数对照为阶段门槛 |
| 样式又只在访问其他页面后出现？ | 页面直接引入所属 CSS；构建依赖检查和各入口硬刷新 | 必须包含有内容的列表，不能只验空态或 DOM 存在 |
| 宽屏变大字号导致按钮和列表错位？ | 字号按角色固定；仅调整分栏和留白 | 三视口逐个测量，同页不出现两种缩放体系 |
| 全局样式覆盖模板、公式或未知模块？ | `--ui-*` 和组件范围；文档子系统独立 | 模板 hash 和正文不变；公式长内容另验 |
| 截掉长文才能“一屏对齐”？ | 保留阅读高度、独立正文滚动和确认区；窄屏允许整页滚动 | 不以页面一屏为完成条件 |
| UI 禁用被当作权限授权？ | 主进程 scope / revision guard、服务端结果核验不变 | 只读 / 历史 / 迟到回执测试必须保留 |
| 卡片像素相同但保存状态含义不同？ | 状态标准明确本机保存、服务端保存、内部转交、官方递交 | 不用通用“成功”替换业务状态 |
| 增加组件是否拖慢首开？ | 共享轻量控件静态依赖，业务面板仍按需加载；不反向引入完整工作台 | U6 做同机对照，按交互耗时判定而非包体 |
| 新方案被误记为用户逐条确认？ | 用户目标与工程参数分开标注，旧需求引用保持 | 不重写业务决定，不虚构设计批准过程 |

这是一轮任务内方案复核，不称为独立第三方评审。

## 6. 验证设计

### 6.1 样例集合

使用隔离账号和合成记录，包含空账号、至少两个不同案件、三个办理类型、一个历史流程、一个无权限记录、一个部分失败结果、一条长案名与无空格英文文件名、长正文 / 公式、运行中 / 停止 / 失败 / 完成任务、未知历史目标。大列表用可重复生成的 200 条合成摘要；它是压力样例，不改变当前业务规模要求。

### 6.2 每类页面的操作闭环

| 类型 | 最少操作闭环 |
| --- | --- |
| 全局列表 | 全新窗口直达 → 等待数据 → 搜索 / 筛选 → 空结果 → 清空 → 打开确切记录 → 返回 → 刷新；核对数量和身份 |
| 当前业务 | 打开指定案件 / 阶段 → 操作原允许动作 → 切到全局 → 返回 → 停止 / 继续或保存；正文、目标和任务记录仍一致 |
| 文件 / 提交 | 选定文件 / 分件 → 取消不产生写入 → 本机草稿保存 → 合成服务失败 → 原输入仍在 → 回读结果明确 |
| 设置 | 当前账号配置 → 编辑 / 取消 / 保存失败 / 再保存 → 切账号时旧回执不覆盖新界面 |
| 弹窗 | 键盘触发 → 初始焦点 → Tab / Shift+Tab → 长内容滚动 → Escape / 关闭 → 焦点返回原触发处 |

### 6.3 性能和记录

先保存同机、同数据、同视口的改造前基线，再测冷开（不少于 5 次）、暖切换 / 本地保存（不少于 10 次）。记录原始样本、median、p95、DOM 可交互与保存回执 / 落盘两个时点。超过基线 20% 且增加至少 100ms 的页面打开 / 刷新，或增加至少 50ms 的本地保存，需要排查并说明后才接受；该门槛是排查标准，不是对任意设备的速度承诺。

模型处理用同一固定合成供应商，只核对 UI 改造有没有附加等待；供应商网络速度、模型质量和缓存真实收益单列。统一 UI 不新增请求、不改变同步并发、不改变保存调用次序，远端写入仍逐项授权。

证据记录版本、平台、路由、viewport、数据类别、加载方式、交互结果、控制台和截图。原生 `.app`、Windows 包内解包、Windows 实机、覆盖安装分别记录；不能用一个平台的 DOM 视口代替另一个平台通过。

## 7. 新模块交付要求

模块说明至少包含：注册位置与路由、页面类别、标题来源、使用的 token / 共享控件、CSS 所有权、数据范围、加载 / 空 / 错误 / 只读状态、滚动区域、主操作、是否写入 / 长任务、取消与恢复、所需证据。样式与页面独立加载检查纳入 [模块接入指南](../development/module-guide.md)；修改模板时在隔离源码副本生成全局和单案两个示例验证。

整套 UI 统一的完成条件是上述页面清单全部迁移并取得对应证据、被替代样式删除、业务行为回归通过。规范文件存在、页面能加载或截图看起来相似，都不单独构成完成。
