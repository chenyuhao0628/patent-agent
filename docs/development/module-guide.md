# 模块接入指南

核对基线：2026-10-12 / 0.22.0。模块是随桌面应用编译的可信源码，注册项变化通过新安装包交付。OpenCode 自动兼容更新和技能 / MCP 更新沿各自入口进行。

## 全局和单案分别注册

| 视图 | 注册列表 | 路由 | 数据范围 |
| --- | --- | --- | --- |
| 全案 / 工作区 | `CUSTOM_GLOBAL_PANELS` | `#/ext-名称` | 当前账号的案件摘要 |
| 单个案件 | `CUSTOM_CASE_PANELS` | `#/case/案件ID/ext-名称` | 绑定的账号、案件、当前阶段 |

两者共用注册校验和 PanelHost，分别声明入口。一个功能需要全案汇总及单案详情时生成两个入口，可以提取共用展示组件，不能靠“有没有当前选中案件”隐式切换范围。全局审查队列与单案稿件审查是不同入口，不是两个同时办理的阶段。

```sh
npm run module:create -- --name case-notes --location global --title 全案笔记
npm run module:create -- --name case-notes --location case --title 本案笔记
```

必须指定位置。生成器在执行后写入 `src/modules/generated/global-case-notes/` 或 `case-case-notes/`，包含 `panel.ts`、`Panel.tsx`、`panel.test.ts`，并插入 `src/modules/custom.ts` 对应列表；这些示例目录在未生成模块的工作区可以不存在。名称仅允许小写英文、数字及连字符；同位置同名拒绝覆盖，路径穿越、符号链接及注册标记漂移拒绝执行。两处同名合法，ID 包含位置，路由按位置区分。手工接入也必须保持 ID 全局唯一、路由在所在位置唯一；启动注册校验是最终检查。

不需要修改 App、PageContent、CaseSpace 的组件分发。禁用模块可设置 `enabled: false`；卸载源码前先移除注册项，旧书签会明确显示不可用，不跳到其他业务页面。

## 数据、刷新和生命周期

模板使用 `useSyncExternalStore(data.subscribe, data.listCases, data.listCases)`。摘要快照在工作区未变时保持同一引用；面板卸载清理订阅，旧接口失效，账号 / 案件 / 阶段代际变化重建面板。不要另存案件主记录或修改返回对象；全局数据接口不提供任意案件写入。此接口是可信模块的工程边界，不是运行不可信代码的沙箱。

默认没有 `enter`、`canEdit`，打开只读页面不会启动任务。单案元数据仅在显式 `canEdit` 允许时获得 `saveMetadata`，字段限于标题、期限、标签和归档；业务写入仍需专用主进程合同及校验。不要从前端拼接文件路径，也不要将全案快照交给单案模型。

全局刷新与单案刷新继续使用各自业务入口，不在渲染、订阅或加载时自动同步。保存通过统一 Store 的有序队列送至主进程仓储。切换页面不停止后台任务；卸载只清理模块自己的监听和临时显示，不能取消其他任务或删除会话。

面板加载由 `panel-loader.ts` 缓存模块代码、发布明确的加载 / 就绪 / 失败状态，`panel-host.tsx` 管错误重试和范围重建。缓存不保存面板实例或案件数据，也不在每次挂载重建 React.lazy。

`requiredCapabilities` 必须来自实际宿主能力；导航与直达路由采用同一检查。`visible` 只控制入口展示，禁止直达还需 `canOpen`。历史页面必须显式声明历史入口并实现目标解析，不能将历史链接投射到当前稿件。

## UI 与样式接入

新增或改造面板遵循 [UI 规范](../design/ui-standards.md)。全局与单案的外框、标题来源、主动作、控件高度、状态语义及数据范围须明确；不同业务可选列表、表格、对话或阅读布局，不能重复创建壳层和页面 padding。

组件直接引入自己的 CSS，共享控件直接引入所需样式；禁止借访问其他模块加载样式，或为获取样式 import 完整业务工作台。共用 token 和 PageHeader 等仍是 [统一方案](../design/ui-unification-plan.md) 的待实施项，接入时先核对实际导出。

模块说明列出空 / 加载 / 刷新失败 / 只读状态、滚动区、按钮权限和 CSS 所有权。验证使用有内容的合成记录，逐项完成独立首开、硬刷新、从全局到单案再返回的样式和目标一致性；只看无错误日志不算视觉通过。

## 写入和长任务

先定义主进程与前端共用合同，对账号、案件、阶段、分支、版本及修订做校验，再实现受管文件操作、保存回执与恢复。业务状态由原 Host 协调；组件发出明确命令，订阅公开进度。写入保留原件 / 人工稿、核验服务端业务结果，记录不确定状态；真实内部转交不能由页面加载触发。

长任务必须验证取消、停止后迟到回执抑制、关闭 / 重开恢复、产物摘要与版本保护。独立复核不继承主讨论或执行会话；会话及缓存按原范围键隔离。

## 可替换适配器

| 类型 | 合同 / 装配 | 必须验证 |
| --- | --- | --- |
| 执行引擎 | `desktop/agent-contract.ts`、`engine-adapters.ts` | 结构化事件、受控工具、取消、文件产物、会话与案件隔离 |
| 外部业务 | `desktop/case-system-contract.ts`、`case-system-adapters.ts` | 账号、个人案件、附件、流程、业务写入回读与不重放 |
| 存储 | `desktop/workspace-repository.ts`、`workspace-adapters.ts` | 账号隔离、旧数据、未知字段、备份、原子保存与作用域 guard |

通过 `create*Adapters` 注册合同版本与能力。未知 ID、版本不符或能力缺失拒绝创建。DesktopService 可注入客户端工厂与仓储，createHostRun 接受 AgentRunner 实现。RuntimeManager 的下载 / 验证机制仍针对 OpenCode，新引擎需另配运行时管理策略。仅在装配或后续任务创建时替换，不改变运行中任务的依赖。

业务客户端合同版本 1 的标准行和内部流转调用沿用贝思兰德语义；其他供应商须在适配器内完成协议映射和业务结果核验。存储 `file(profile)` 是本机记录 / 日志的受管位置约定，替代存储仍需提供稳定位置。凭证与共享任务不得混入其中。生产仍是 OpenCode、贝思兰德和本机文件，声明能力及测试替代实现不代表第二个真实供应商已验收。

## 验证与升级

```sh
node --experimental-strip-types --test src/modules/generated/*/panel.test.ts
npm test
npm run build
```

生成模块后执行第一条命令，亦可将这些测试路径纳入项目测试命令；初始仓库不含示例模块。使用隔离数据的原生桌面打开全局入口和两个不同案件入口，核对账号 / 案件切换、直达 / 缺失路由、只读、卸载后旧回调与延迟加载。新后台能力还需真实文件、取消与恢复验证。保留旧数据，安装包保留或清理按当次要求；不把编译成功等同安装、真实模型或生产业务验收。
