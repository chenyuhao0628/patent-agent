# 文档职责与维护流程

核对基线：2026-10-12，代码 `027c9de`，应用 0.22.0。项目采用同一条管理链：确认需求 → 当前计划 → 实现 → 验证 → 交付 → 归档。本文规定文档归属，不增加业务或审批要求；执行规则仍以 [AGENTS.md](../../AGENTS.md) 为准。

## 每类信息只有一个主要维护位置

| 要回答的问题 | 主要维护位置 | 更新触发条件 |
| --- | --- | --- |
| 产品是什么、从哪里开始 | [根 README](../../README.md) | 产品入口、当前版本或交付状态变化 |
| 应该做什么、哪些决定生效 | [需求索引](../../REQUIREMENTS.md)及 `docs/requirements/` | 用户明确确认或修改需求；不因实现完成删除需求 |
| 现在做什么、还有什么差距 | [EXEC_PLAN.md](../../EXEC_PLAN.md) | 当前任务推进、发现实现差距或取得新验收证据 |
| 当前代码如何工作 | `docs/architecture/`、[代码对照表](traceability.md) | 接口、数据、权限、生命周期或参数变化 |
| 开发者如何修改与验证 | [开发入口](../../DEVELOPMENT.md)、`docs/development/` | 命令、依赖准备、模块接入或开发流程变化 |
| 用户如何操作 | [使用说明](../USER_GUIDE.md) | 界面入口、触发条件、操作效果变化 |
| 哪个包可以使用、验证到哪一步 | [交付索引](../releases/README.md)、当前版本测试说明、`release/release-manifest.json` | 新包核验、包清理或当前版本验收变化 |
| 为什么这样设计、当时如何复核 | `docs/design/` | 新方案、取舍或实施状态变化；必须标明计划 / 已实施 / 已被取代 |
| 当时做过什么 | `docs/archive/` | 当前任务结束或历史决定从入口移出 |
| 凭什么认为通过 | `evidence/` | 每次指定范围的验证；保留原文件名、版本、命令与结论边界 |

需求不等于已经实现，实现不等于所有环境都已验收。代码出现偏差时保留需求，把差距放入当前计划；在架构和使用说明中如实说明当前行为。测试数量必须带版本和证据入口，不能沿用旧数量声称本次重新通过。

## 文件类型与范围

- 当前入口：README、REQUIREMENTS、DEVELOPMENT、EXEC_PLAN 及 docs/README；保持简洁，详细内容按模块引用。
- 现行参考：requirements、architecture、development、project、USER_GUIDE 和当前版本 TESTING；与当前代码 / 已确认要求对账。
- 有状态的方案：design；实施前的“当前版本”和限制只适用于方案形成时，完成后链接实现及证据。
- 历史：archive、旧版本 TESTING、旧根入口；不作为活动 TODO，不据此宣称旧安装包仍存在。
- 证据：既有截图、JSON、日志及报告保持原路径。中间失败结果和最终通过结果分别标识，原始证据不能为了结论一致而改写。
- 运行资源：`resources/reply-rules/`、`resources/standard-skills/`、`resources/document-templates/` 由应用加载，属于产品规则与模板；改动会影响业务，不作为普通开发文档改名或精简。
- 外部参考及案件：`1-贝思兰德云API/`、`work/`、来源仓库和真实案件资料不是开发指令。本次只确认其角色与引用，不重写材料或读取凭证。

## 更新顺序

1. 先确认用户要求、Git 状态、对应需求及源码。一个新需求落到对应模块，根索引只保留决定摘要。
2. 当前工作放入 EXEC_PLAN；已完成任务迁入 archive，并保留代码 / 测试 / 制品链接。
3. 行为或接口变动同步更新架构和使用说明；开发命令与模板变动同步更新开发指南。
4. 验证后写证据，注明代码版本、合成 / 真实数据、平台以及未覆盖范围；交付后才更新实际安装清单。
5. 整理文档时检查本地链接、标题锚点、代码路径、命令、版本、重复状态与被覆盖的旧决定。纯文档变更不升版、不重打包、不新增机械业务测试。
6. 检查 diff 并按当前授权提交。已有历史证据只修复索引或补充解释；需要纠正历史结论时新增带日期的更正依据，保留原报告。

## 兼容旧入口

旧 `CORRECTION_PLAN.md`、`project_analysis.md`、`design/PROTOTYPE.md`、`design/PAGE-MAP.md` 保留短入口；已有 TESTING 文件保持版本号与路径。设计和证据不为视觉整齐而大范围改名。新文档应先选择上述职责，避免再建第二套进度表、每日流水或未维护的交接清单。
