# 案件管理与办理阶段

> 已确认需求；由根目录 [REQUIREMENTS.md](../../REQUIREMENTS.md) 索引。实现归档不使需求失效，本文不单独声明实现或验收完成。

## 案件与阶段

- 同一案件只有一个当前办理阶段
- 案件界面只展示当前撰写 / 答复 / 补正业务入口，过去业务进入办理历史；不因保留旧稿而并列显示为当前业务（2026-09-30 确认，仅局部功能调整，不重构项目）
- 历史阶段可以查看
- 历史阶段不能与当前阶段同时开工
- 撰写、答复、补正不能在同一案件同时开工
- 多个案件可以并行
- 完成并提交当前工作后，收到后续通知才进入下一办理
- 官方结论（授权 / 驳回）只锁定结论所属流程；之后出现的复审等新内部流程恢复为可办理的当前阶段（2026-10-01 确认）
- 未记录结论所属流程的旧数据维持整案锁定；案件归档与结案维持原锁定口径，恢复办理须人工确认（2026-10-01 确认）
- 按贝思兰德 `CaseId` 归并为一个案件
- 一条远程流程不单独建案
- 只同步分配给当前用户的案件
- 只同步由当前用户负责的案件
- 新案件按案件落盘
- 新通知按轮次落盘
- 新流程按轮次落盘
- 落盘不覆盖原件
- 落盘不覆盖草稿
- 落盘不覆盖历史成果
- 一个未结束的内部流程自动成为当前阶段
- 当前阶段仍有效时，其他未结束流程不替换当前阶段
- 多个未结束流程且当前阶段无效时，必须人工选择
- 用户可以切换当前阶段
- 当前阶段经主进程确认后生效
- 收到新通知后进入新的当前阶段
- 流程名称含「补正」时，当前业务为补正
- 「取消提出申请」不归入提出申请
- 流程名称含「复审」「答复」或「审查意见」时，当前业务为答复
- 流程名称含「提出申请」或「撰写」时，当前业务为撰写
- 未能归入申请、答复、补正、审查的业务归为「其他」
- 「其他」不是结案
- 业务在界面上区分申请、审查意见、补正

## 案件库

- 支持搜索
- 支持筛选
- 支持排序
- 支持期限提醒
- 支持标签
- 支持归档
- 支持批量归档
- 支持按公司名称查看
- 支持按专利类型筛选
- 支持按办理业务筛选
- 支持拖动列宽
- 当前状态分为：待处理、办理中、流转中、等待官方、已授权、已驳回、已结案、其他
- 当前状态筛选与上述分类一致
- 按当前状态排序时使用该分类顺序
- 已授权、已驳回、已结案不进入在办和催办
- 已官方递交或已收到回执时进入等待官方
- 等待官方不显示内部办理人
- 等待官方不是结案
- 内部流程结束不是已结案
- 离开个人案件不是办理中
- 个人流程状态 500 本身不是已交官方
- 只有递交证据为已递交或已收到回执时才算等待官方结果
- 需要交官方但没有递交证据时，显示官方递交待核验
- 明确不需要交官方且内部已结束时，显示等待后续流程
- 只在读到 `IsFinishCase=true` 后做本地归档
- 本地归档不向贝思兰德写入结案

## 期限

- 非提出申请的业务，官方期限优先
- 无官方期限时使用贝思兰德计算期限
- 提出申请使用内部期限
- 期限必须显示来源
- 不接入 CPC

## 2026-09-29 实测修复补充要求

- 同一远端流程 ID 被退回到可办理状态时，恢复正确办理阶段、节点与权限，保留原稿和历史
- 提交结果回读及退回刷新同时更新全案，不仅更新提交日志；已发送但未确认的请求仍不得盲目重发
- 先建立本地案件撰写，后期开卷后支持显式关联当前账号已同步的远端案件；同名同号不自动合并
- 关联前展示双方身份并确认；保留双方原目录、原件、稿件、阶段成果、对话和历史版本；冲突不静默覆盖
- 关联后同一远端案件只显示一个当前办理入口；保留关联来源记录，历史案件不成为第二个可写入口
- 关联不向贝思兰德新建案件、上传文件或执行转交；无远端办理流程时不能伪造转交
