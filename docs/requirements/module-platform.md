# 模块平台与统一数据管理

2026-10-12 用户明确授权：完整规划与复核后，实现面板注册与宿主、统一数据管理、可替换适配器和模块接入模板，分阶段检查并本地提交，最终阶段完成后结束目标。

- 新模块复用统一导航、路由、能力 / 访问判断和宿主生命周期，减少新增业务页面时分散修改壳层。
- 全案视图与单案视图分别注册：全局入口绑定当前账号的案件摘要，单案入口绑定具体案件与阶段。同一功能提供两种视图时分别声明入口，可以复用组件；不将全案数据自动送入单案模型上下文。
- 对照改造前后的页面冷 / 暖打开、刷新、保存可见与落盘、固定合成供应商任务耗时；明显退化先修复，不能用包体分块大小替代耗时结论。
- 案件数据使用统一身份、权威记录、读取和受控写入；继续隔离账号、案件、阶段、分支与版本。共享材料、任务 / 对话及凭证按既有边界保存。
- 引擎、外部业务系统和存储有明确适配合同及装配入口，以实际可替换测试验证，不把类型接口等同于真实供应商支持。
- 模块接入模板须可生成、注册、构建和加载；新增后台写入 / 长任务仍需相应合同及校验。
- 保留既有案件、答复、撰写、独立审查与内部流转语义；只读面板不自动开始办理。旧 URL、历史记录和用户稿件保留。
- 本次授权包含本地实现、回归、打包及逐阶段本地提交，不包含推送、发行发布、覆盖安装或真实生产业务写入。

实施范围、步骤及实施前复核见 [模块平台方案](../design/module-platform.md)，当前进度只维护于 [EXEC_PLAN.md](../../EXEC_PLAN.md)。

## UI 对齐与页面统一

2026-10-12 用户追加要求：完整规划并设定 UI 规范和设计标准文档，要求 UI 对齐及各类页面统一。

- 覆盖全局工作区、单案全部页面、八类设置、弹窗、任务与文件等跨页控件。
- 同类页面的标题、内容起线、工具栏、控件、列表动作和状态呈现保持一致，窄窗口、宽屏和加载顺序不造成布局混乱。
- 全案与单案保持分别注册及数据范围，沿用单案唯一当前办理、保存、确认、可选审查、权限和文件保护规则。
- UI 规范给出可实施的参数、组件职责和验收标准；完整迁移先规划及复核，实际实施结果分阶段记录。
- 具体尺寸、色值、token 和组件命名由工程设计确定，见 [UI 1.0](../design/ui-standards.md)；页面盘点与阶段方案见 [统一方案](../design/ui-unification-plan.md)。文档制定不代表所有页面已迁移，也不改变现有业务要求。
