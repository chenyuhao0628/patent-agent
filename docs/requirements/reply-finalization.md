# 答复、补正与定稿

> 已确认需求；由根目录 [REQUIREMENTS.md](../../REQUIREMENTS.md) 索引。实现归档不使需求失效，本文不单独声明实现或验收完成。

## 答复与补正

- 答复支持首次审查意见
- 答复支持后续审查意见
- 答复支持补正
- 答复步骤为材料核对
- 答复步骤为策略讨论
- 答复步骤为起草修改
- 答复步骤包含可选独立复核
- 答复步骤为用户定稿
- 分析、选定策略、起草、人工编辑、独立复核、定稿各有状态
- 分析、选定策略、起草、人工编辑、独立复核、定稿各有触发条件
- 正式办理默认执行当前步骤
- 可以切换为仅讨论
- 分析未完成时不能选定策略
- 未选定策略时不能起草
- 分析不能直接产生定稿
- 分析中断后可以继续同一分析
- 材料、分类变更或重新分析归档旧分析后，旧分析下的稿件不自动作为当前稿；由用户显式选择后才采用（2026-10-01 确认，与撰写侧同规则）
- 模型自述不能代替材料读取
- 模型自述不能代替产物校验
- 模型自述不能代替用户确认
- 答复规则以 DSH 按类型组合的规则为基准
- 业务语义与该基准不同时必须能够对照
- 答复和补正共用「本案对话」
- 长回复在对话区内滚动
- 输入框和状态在长回复时保持可见
- 运行状态显示当前动作、耗时和最近活动
- 供应商返回的思考内容可以展开
- 供应商未返回思考时显示暂无
- 思考内容不进入正式回复
- 思考内容不进入后续模型上下文
- 停止或退出后保留已输出文字、思考和任务记录
- 重开后由用户选择继续或重试
- 继续使用当前上下文
- 重试在新分支重新执行本轮
- 可以编辑历史用户消息并重新生成
- 可以切换到旧分支
- 运行中编辑历史用户消息并重新发送、或重新生成历史回复时，先停止当前任务；普通补充消息进入下述待发送队列
- 旧任务的迟到输出不进入新任务
- 切换分支不回滚案件文件
- 切换分支不回滚业务状态
- 恢复时用本机执行记录阻止重复命令、下载和安装
- 执行结果未明时先核对
- 自定义 MCP 不在恢复时自动重放
- 已有成果按当前文件和版本重新核对
- 不恢复模型内部推理位置
- 运行中的新消息排队
- 运行途中不追加到当前模型请求
- 队列跳过已失败项并继续后续项
- 空的附加讨论可以删除
- 有内容的附加讨论可以归档
- 有内容的附加讨论可以恢复
- 主讨论受保护
- 独立复核讨论受保护
- 有关联任务的讨论受保护
- 独立复核讨论不能推进主流程
- 各办理步骤可以退回上一步
- 补正字段为文件名称、具体位置、补正前、补正后
- 补正可以有多条
- 补正保留服务端已有行标识
- 补正保留服务端其他字段
- 补正条目在提交页「本次材料」编辑
- 补正本机草稿写入 `04_内部说明/transfer-*.json`
- 保存补正本机草稿不写贝思兰德
- 切页、选文件或离开提交页时先保存补正本机草稿
- 已有补正条目且无文件的草稿保留
- 无补正条目的空草稿不保留为有效草稿
- 补正的业务表单只核摘要附图
- 补正的业务表单展示已保存条目摘要
- 提交补正时写入 `100006`
- 不生成补正说明 Word
- 不上传补正说明 Word
- 编辑补正字段产生新版本
- 编辑补正字段使旧复核失效
- 材料核对可以匹配原始申请文件
- 原始申请匹配结果由用户勾选后进入分析

## 定稿与稿件

- 起草和修订输出本次修改部分的完整正文
- 界面可核对权利要求书、说明书和摘要
- 无修改时保存空修改范围
- 不能从修改建议推测完整正文
- 旧版本缺少完整正文时先补齐再复核
- 采用稿后停留在起草修改
- 定稿页可以保存空修改范围
- 定稿前可以微调正文
- 定稿前可以微调补正条目
- 未保存的微调阻止确认定稿
- 从未分析的手工稿可以定稿
- 过期分析必须重新分析后才能定稿
- 已归档分析必须重新分析后才能定稿
- 可以撤销定稿
- 撤销定稿保留正文
- 撤销定稿保留五书拆分
- 撤销定稿保留补正条目
- 撤销定稿保留定稿记录
- 定稿按 DOCX 模板生成意见陈述书
- 定稿生成各修改部分
- 定稿生成修改依据
- 定稿生成内部复核说明
- 正式目录不新建 TXT 替代品
- 正式目录不新建 Markdown 替代品
- 原始文件保留
- 完整稿保留
- 历史版本保留
- 文件身份明确
- 文件所属案件明确
- 文件所属轮次明确
- 文件有效版本明确
- 定稿后外部修改的 Word 保留为成果
- 外部修改标记为外部已修改
- 外部修改的正文可以载入微调编辑器
- 定稿后刷新不因外部修改中断办理
- 历史稿件恢复生成新版本
- 历史稿件恢复保留当前稿件
