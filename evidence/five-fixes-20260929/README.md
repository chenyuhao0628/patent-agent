## 五项修复及回归依据

1. **同流程退回回写**：恢复当前办理阶段、节点、办理人及权限，保留官方已确认结果优先级。服务重开测试覆盖等待态/状态 500 退回当前答复流程后的持久化；转交已确认结果先落盘，再定向回读本案，不调用全库同步。
2. **本地 Word 内部转交**：已关联案件使用本地文件不读取 AI 稿件。保留有效人工接收人选择；只在实际候选中存在唯一杨佳时默认选中，多同名或冲突身份不猜测。保存、重开、转交及权限移出/退回均有合成回归；没有实际转交给杨佳。
3. **复用远端完整材料**：按有效 FileNo、五书、完整申请文件及 XML 设置核验，完整远端申请材料可直接恢复并保存表单，不强制重复上传。逐项缺失、全零 FileNo、缺完整申请文件或 XML 设置均被准确识别。
4. **显式关联本地与已开卷案件**：核对双方身份和确认令牌，不按同名同号自动合并。主案保留原本地 ID、目录和稿件，来源案保留原目录与历史并只读归档；后续同步按远端 CaseId 只更新主案。专业阶段记录继承并可重开。
5. **阶段真实 DOCX 与确切版本预览**：使用 `resources/document-templates/reply.docx` 生成阶段文档，保留 Markdown，按案件、流程、任务和摘要读取对应 DOCX。标题、强调、表格、公式及内嵌图片有回归；旧 Markdown 按需转换一次，不覆盖原件。无法安全转换的公式、未闭合标记及不支持的图片来源明确失败，不以损失内容的文件冒充成功。正式申请模板 `application.docx` 未被替换。

### 关联发布与中断恢复

私有工作区是身份提交点；私有 `case-link-publication.json` 和共享 `.case-link-pending.json` 协调新流程工作稿、主案索引、来源案索引的发布。共享标记存在时拒绝导入部分身份。测试覆盖准备、私有提交、三份文件分别发布后的中断、外部修改冲突、并发操作、目标已有稿件、冲突版本 ID、损坏恢复记录，以及发布完成后带/不带标记的清理重试。后续人工稿件不会被清理重试覆盖。

出现可恢复中断时，可在发起关联的电脑重新启动，或使用“设置 → 文件与目录 → 刷新读取工作目录”。若目标内容已被外部修改，会保留原文件和恢复记录并阻止继续写入，不能自动选择覆盖哪一份。此机制不是云盘跨设备强一致事务；应先等待同步完成，再由一台电脑编辑同案，旧版客户端不理解新增发布标记。

退回记录在旧发送记录被标记历史、但新核对记录尚未落盘时中断，重开仍可回读当前服务端材料恢复，保留原发送目标，不自动再次发送。

## 隔离桌面验证

`prepare-desktop.mjs` 创建独立临时数据目录和两份合成案件，使用真实模板生成含标题、粗体、表格、列表及分式的 DOCX。`desktop-fixture.json` 仅记录本次临时目录、合成案件 ID 和文档摘要，不是可移植交付物。脚本直接注入合成已完成阶段记录，不代表真实模型质量。

实际操作：

- 从本地先写案件打开撰写页，确认预览来自已保存 DOCX，不直接显示标题和强调的 Markdown 标记；查看表格及公式下半部。
- 在概览打开显式关联，选择已开卷合成案，核对远端身份并勾选确认后执行。
- 确认主案仍使用原本地 ID 与目录；当前办理变为远端提出申请/文件准备，双方稿件保留。
- 关联后进入撰写页，原阶段 DOCX 仍可预览。
- 正常退出测试 Electron，再用同一隔离目录和最终构建启动；案件库只有一个未归档主案，办理节点与承办人保留，阶段 DOCX 仍可读取。
- 在案件库筛选已归档，打开来源案；页面显示“关联来源历史”，原稿在“历史内容 · 只读”弹窗中完整显示，无编辑或转交入口。
- 验证结束正常退出测试实例，进程退出码 0；合成目录保留，不影响真实应用用户数据。
