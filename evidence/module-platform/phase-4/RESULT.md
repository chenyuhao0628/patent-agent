# 阶段 4：可替换适配器

2026-10-12。生产装配已通过执行引擎、业务客户端、工作区存储三个注册入口创建；未知标识、合同版本不符、能力缺失明确失败。执行合同独立于 OpenCode；DesktopService 和内部流转使用业务客户端接口；本机读取、写入和迁移备份归存储适配器。

## 验证

- 99/99：adapter-contracts、agent-integration、runtime-manager、integration、baseland-hardening、baseland-transfer、sync。
- `npm run build`：类型、前端和 Electron 主进程构建通过。
- 独立的内存存储与默认文件存储经过同一服务的保存、重开、账号隔离与失效写入验证；没有继承文件实现。
- 默认贝思兰德客户端（合成 HTTP）与独立客户端经过同一注册器 / DesktopService 的登录、案件、附件和取消验证。
- 替代执行器经注册器与 createHostRun 验证独立复核输入、结构化增量、材料范围、产物文件校验及停止后迟到结果抑制；业务 Host 不认识实现类型。
- 真实捆绑 OpenCode 2.0.27 经生产注册入口完成四模型协议、会话保留 / 重启复用、跨案隔离、停止、压缩后续接与旧私有上下文排除验证，见 [结构化结果](runtime/acceptance.json)。全部材料与供应商均为本机合成。

## 复核

检查了实际装配路径和改动 diff；生产不绕过注册工厂。存储迁移备份从服务移入仓储，保存与身份 guard 未放宽。已有重授权测试针对具体 HTTP 实现时显式收窄为 BaselandClient，未向公共合同泄露 fetcher。

首次新合同测试仅因取消错误中文文案与英文断言不符失败，修正断言后全部通过，没有改变生产取消逻辑。

业务客户端版本 1 仍以现有标准行和内部流转协议为合同；新供应商必须在适配器中完成协议映射和业务结果验证。此验证不表示已支持第二个真实业务系统、第二个真实引擎或任意可安装前端插件；没有生产业务写入。
