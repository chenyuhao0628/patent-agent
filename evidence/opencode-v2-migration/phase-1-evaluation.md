# 阶段 1：v2 迁移评估

日期：2026-10-12（北京时间）；评估应用基线 d2270e0 / 0.20.1。用户已明确授权升级 v2，并要求自动兼容更新，不固定补丁版本。当前实施状态只维护在 EXEC_PLAN.md。

## 决策与边界

推进 v2 适配。官方迁移说明明确服务端 API、插件 API 和终端配置有破坏性变化；现有工作台直接调用 v1 HTTP，因此不能只换文件。应用不依赖 v1 插件或终端 UI，模型、MCP 和权限可迁移。没有发现必须继续停留在 v1 的产品依赖；后续仍需以实际工具 / 模型协议 / 权限集成测试确认候选可用，不能用本阶段基础启动代替。

截至检查时，官方 npm CLI latest 为 2.0.27，macOS arm64 原生包 latest 仍为 2.0.26，Windows 原生包已为 2.0.27。选双平台已完整发布的 2.0.26 做本次兼容样本；应用将按实际接口能力与摘要验证后续候选，不写“仅允许 2.0.26”的生产限制。来源与 SHA-512 / SHA-256 见 download-evidence.json。

## 本机对照

相同 macOS 主机、合成新 HOME / XDG、无凭证和真实案件，单独启动服务三次。v1 调用 /global/health，v2 调用其官方 /api/info；同为首次健康响应，不包含模型生成、工具或项目首次加载。

| 运行时 | 三次启动 ms | 中位数 |
| --- | --- | --- |
| 1.18.30 | 1746 / 931 / 920 | 931 |
| 2.0.26 | 626 / 615 / 634 | 626 |

本机小样本中位数下降约 33%；不能外推为模型任务、所有设备或 Windows 的性能提升。v2 随后创建独立合成会话三次均 HTTP 200。原始记录见 startup-probe.json。Windows 文件已下载和核对完整性，尚未执行。

## 已核对的官方接口差异

- v2 使用 /api/session、/api/session/{id}/prompt、分页消息和显式执行 / idle 事件。旧 prompt_async 和 v1 message/part 结构必须适配。连接模型依然由工作台凭证代理控制。
- 原生配置使用 agents、providers、permissions 有序规则、mcp.servers；MCP 默认 Code Mode，工作台将明确使用直接工具模式，保留工具白名单和日志 / 产物校验。
- 每案会话隔离要继续细分阶段、主讨论、独立复核和重试分支；不能借缓存把其他案件或过期材料混入。后台记录与共享文件目录分开。
- 本机持久会话、供应商 prompt cache、自动压缩是三个不同机制，分别配置和验收。官方提供缓存读取 / 写入 token 统计；“发出缓存键”不能报“命中”。
- 官方 warming 通过额外模型请求保持近期会话热度，默认关闭并会计费；将作为明确可控功能，普通上下文缓存不依赖无声定时计费。
- 自动更新由工作台拥有：官方来源下载、完整性与兼容性验证、任务空闲后切换、保留上一可用运行时；不允许底层在当前任务中自行替换。

官方页面地址与核对日期保存在 official-sources.json。网页搜索工具本轮未返回可用结果，已直接读取官方站点和 npm 元数据；未把搜索摘要作为依据。最初辅助探测误用了 /api/server，按已获取的 API 契约改为 /api/info 后得到上表结果；错误路径不构成 v2 故障结论。
