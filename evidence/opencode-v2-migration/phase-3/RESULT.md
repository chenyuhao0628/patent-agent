# 阶段 3：OpenCode v2、会话、缓存与更新

日期：2026-10-12；本阶段源码安装版本仍为 0.20.1，最终 0.21.0 安装包在阶段 5 构建。项目打包源已换为官方 OpenCode **2.0.27**，这是本次已验证快照，不是补丁版本限制。旧 1.18.30 二进制和现有 0.20.1 安装包保留，没有覆盖用户安装。

## 实现与检查

- v2 原生 providers / agents / permissions / mcp.servers 配置；使用 `/api/info`、session 创建 / prompt / active、分页消息和原生事件。允许新增字段及后续稳定版本，通过实际能力测试决定是否启用。
- 内置及自定义 MCP 明确采用直接工具模式；原生工具 deny-all。连接后等待稳定窗口，因为官方 `packages/core/src/tool/mcp.ts` 的工具注册有 100ms 防抖。额外更新实测曾复现“连接成功、工具尚未注册”，补齐等待后完整链路通过。不能将等待首个 HTTP 健康响应等同于工具已就绪。
- 账号、案件、阶段、讨论、分支、任务种类、材料 / 稿件和模型范围分别绑定。相同有效范围的完成会话持久保存并复用 session ID；失败 / 停止记录保留，续办从公开上下文与检查点发起新的执行。旧 v1 档案不删；旧公开对话在下一任务中进入 v2 的当前公开上下文。
- 后台数据库位于本机 profile，任务输出仍逐任务保存。新运行时使用上一空闲数据库的独立副本，回退不打开新引擎改过的原数据库。真实 v2 数据库复制后保留同一 session ID，另有并发锁、范围变化、回退与坏记录回归。
- 本地完整 transcript 与发给模型的上下文分开管理：新任务以应用当前公开对话、确认状态和冻结材料为准，不重放旧隐藏推理及旧工具结果；本任务内工具 / 推理协议交换维持。稳定隔离的 Responses 缓存键、store=false、自动压缩和四协议缓存用量读取已经核对。普通缓存不启动定时付费预热。
- 自动更新默认开启，应用运行时每 6 小时及启动时检查。官方 npm 原生包经 SHA512 校验后只解出目标普通可执行文件，不执行 npm 安装脚本；四协议合成检查、工具权限、取消、会话与缓存验证通过后才激活。所有任务租约释放后切换；校验失败保留当前版本，运行异常为后续任务回退，不自动重放失败业务。
- 设置页显示版本、更新状态、开关、立即检查及回退；答复 / 撰写 / 审查任务展示本机会话与缓存统计。Chat 输出限制沿用原生 max_completion_tokens 或 max_tokens，只发送其中一个，避免兼容接口拒绝互斥字段。

## 证据

- **全量 827/827**，无失败 / 跳过 / 取消；类型、前端和桌面 bundle 构建通过。
- **实际 macOS 2.0.27 二进制 + 合成模型**：Responses、Chat Completions、Anthropic Messages、Gemini 全部完成当前材料读取、拒绝跨案读取、拒绝原生工具、保存产物与正常结束。八次后台启动均拒绝无凭证会话请求；停止路径返回 aborted；同案重开及复制数据库复用会话，异案 session 不同；收到模拟的 cache token 统计。
- **实际更新状态机 + 实际候选二进制检查**：持有任务时维持 2.0.26；候选 2.0.27 验证后 pending；最后租约释放才激活；持有新任务时回退同样 pending，结束后回到 2.0.26。此项使用已由正式下载器完成 SHA512 校验的官方文件副本，没有重复下载；下载与恶意归档 / 摘要拒绝另有真实下载及回归。
- **实际 Electron 开发桌面 + 独立 userData**：设置 → 应用与更新，显示 2.0.27；切换自动更新开关后回读持久状态一致，立即检查通过。1440×900 CSS 视口无横向溢出。当前浏览器技能面向已登录 Chromium，不控制原生 Electron；此处用原生窗口的独立 CDP，未安装新浏览器依赖。现有 KaTeX_Size3 内联字体 CSP 错误仍在，进入阶段 4 修复，不声称控制台零错误。
- **Windows**：官方 x64 baseline 构件下载、摘要和 PE 文件头通过；没有在 Windows 上运行或安装。阶段 2 的 Windows Job Object 实机缺口保持。
