2026-10-12。基于阶段 4 提交 `5e9f89c` 完成收尾，源码与安装清单均为 **0.21.0**，捆绑 OpenCode **2.0.27**。本轮仅本地提交和制品生成，没有推送、对外发布、覆盖用户安装或真实业务写入。

## 收尾发现与修复

强制触发 v2 压缩时发现：引擎可能只发送较早历史进行摘要，缺少当前任务标识；原代理在当前任务已发送过一次请求后放行无标识请求，可能把前一任务的私有摘要重新发给模型。此问题不等于跨案件串话，但违反了后续任务只使用当前公开上下文的边界。

现在每次任务的公开 prompt 从任务标识开始。代理保留最近已核对的本任务上下文；当旧历史压缩请求没有标识时，用该上下文或本任务公开初始上下文重新生成摘要。带当前标识的序列化 checkpoint 会删除标识之前的旧摘要和工具文本；没有实际发送本任务压缩请求时，不接纳无标识 checkpoint。所有路径删除供应商旧 `previous_response_id`。本任务内已经核对的工具进展与压缩摘要可以继续使用。

新增 12 项四协议回归，覆盖旧摘要压缩、首请求前压缩、未授权 checkpoint、序列化和多段消息中的旧上下文。自动候选验收增加每种协议两轮强制压缩与续接，并断言后续任务的任何模型请求均不含前一任务的私有摘要。未来版本须通过该实际行为验证，不能仅凭版本号自动激活。

[修前 / 修后合成复现](compaction-reproduction.json)：修前第二轮无任务标识的压缩请求出现 `OLD_PRIVATE_DETAIL`；修后两轮完成并复用会话，第二轮所有请求均不含该标记。该探测通过报告 29000 input tokens 触发 32000 context window 的压缩，验证引擎压缩路径，不代表真实长文质量或真实供应商 token 计数。

## 会话、缓存与更新结论

会话按账号、案件、办理阶段、讨论 / 分支、业务种类、有效上下文和模型隔离，并保存在本机；完成任务可续接，独立审查不混入原执行上下文，停止 / 失败任务不恢复旧隐藏执行。公开历史与产物保留。

代理允许供应商缓存，Responses 使用作用域独立的缓存键并关闭响应存储；界面显示供应商报告的缓存用量和自动压缩次数。已验证合成缓存统计，不把它称为真实命中率。定时付费预热关闭。

后台默认启动时及每 6 小时自动检查官方更新，下载后核验完整性并运行兼容性检查，无任务时切换，保留上一可用运行时和旧数据库以便回退。当前 2.0.27 是构建快照，没有永久补丁版本固定；不兼容候选保留当前可用版本。
