# 实施例、对比例、实验例与编制数据

## 先确定证明目的

不得先追求数量再填内容。对每一项拟写内容先回答：

1. 对应哪个创新点或权利要求特征；
2. 需要证明可实施性、参数范围、必要性还是技术效果；
3. 最少需要多少组才能完成证明；
4. 哪些条件必须保持一致。

## 实施例

- 用于详细说明技术方案如何实施，并支持权利要求概括的范围。
- 一个实施例足以支持时不机械增加。
- 保护范围较宽且一个实施例不足时，设置具有实质差异的实施例。
- 涉及数值范围时，优先覆盖两端值附近；范围较宽时增加中间值或优选值。
- 每个实施例开头写明目的，结尾说明其支持的技术特征或参数范围。

## 对比例

- 围绕核心区别技术特征设置，不为常规特征机械设置对比例。
- 优先采用删除特征、替换特征、参数越界或最接近常规方案。
- 除待验证变量外，其余材料、步骤、设备和测试条件尽量一致。
- 明确说明缺少或改变该创新特征后出现的问题，从而证明其重要性。

## 实验例或测试例

写明：

- 测试目的；
- 样品组、对照组和分组依据；
- 仪器、环境和测试条件；
- 样本量、重复次数和数据处理方法；
- 指标定义、单位和计算公式；
- 结果表；
- 与创新点和技术效果的对应分析。

## 编制数据

数据缺失而用户要求或技术效果需要数据支持时，可以编制数据。

### 约束模型

生成数值前先建立并记录：

- 自变量、因变量和控制变量；
- 合理上下限、单位、有效数字和理论极限；
- 单调、非单调、饱和、阈值或最佳区间关系；
- 适用的质量守恒、能量守恒、配比总量或其他技术约束；
- 对比例相对于实施例的预期变化方向；
- 重复测试的合理波动范围；
- 派生指标的计算公式和误差传递关系；
- 不允许出现的数值组合。

约束关系不能解释时，先修正技术机理或测试设计，不直接填数。

### 编制顺序

1. 从创新点和预期技术效果确定指标。
2. 从实施方案和领域常识建立约束模型。
3. 先确定实施例与对比例的控制变量，再生成数值。
4. 必要时设置端点值、中间值、优选值、均值、标准差或误差指标。
5. 复算所有派生指标，并检查表格与文字结论。

### 形式与一致性检查

- 单位、有效数字和小数位统一；
- 数值符合技术机理和测试条件；
- 参数变化与效果变化方向一致；
- 实施例、对比例和实验例能够相互对应；
- 不出现物理上不可能或量级明显异常的数值；
- 不机械使用等差数列或完全线性结果；
- 控制变量明确，不同时改变多个关键因素；
- 表格、正文、摘要和有益效果中的数据一致；
- 不编造不存在的仪器原始记录、检测报告编号或第三方证明。
- 能够由公式确定的派生指标必须实际复算，不得只凭趋势估计。

## 双输出要求

### 正式申请文件

- 只呈现实施例、对比例、实验例、测试方法、数据和结果分析。
- 不写入“编制数据”“模型生成”“模拟数据”等内部来源说明。

### 内部《编制数据说明》

使用 `assets/compiled-data-record-template.md` 另行生成，至少记录：

- 数据所在章节、表号和数据项；
- 对应创新点和证明目的；
- 编制假设、量级依据和变化规律；
- 计算公式和派生值；
- 控制变量；
- 申请文件采用的最终数值；
- 以后取得实际数据时的替换位置。

两份文件的数据必须逐项一致，但内部说明不得并入正式申请文件。
