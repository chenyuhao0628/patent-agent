# 最终复核

最终复核必须同时完成脚本机械检查和模型全文阅读。任何一层都不得省略。

## 第一层：脚本机械检查

只检查已经确认的正式申请文件。查新报告、审查评估、修改说明、状态卡、确认记录、内部《编制数据说明》和其他过程文件不得作为格式检查输入。

命令中的 `<Python命令>` 按运行环境选择：

- macOS/Linux：`python3`；
- Windows PowerShell：优先使用 `py -3`，未安装 Python Launcher 时使用 `python`。

正式文件为 DOCX 时，先转换为临时 Markdown：

```bash
<Python命令> <skill目录>/scripts/docx_to_md.py <正式申请文件.docx> -o <临时目录/正式申请文件.md>
```

如果转换器检测到修订，必须显式追加 `--revision-mode accepted` 或 `--revision-mode original`；未选择模式时转换会失败。两种模式的结果都只能作为过程稿，仍须核对原 DOCX 或渲染页。

然后对转换结果或原有 Markdown、文本文件运行：

```bash
<Python命令> <skill目录>/scripts/audit_patent_draft.py <正式申请文件.md或目录>
```

Windows PowerShell 示例：

```powershell
py -3 "$env:USERPROFILE\.codex\skills\draft-cn-invention-patent\scripts\docx_to_md.py" "申请文件.docx" -o "申请文件.md"
py -3 "$env:USERPROFILE\.codex\skills\draft-cn-invention-patent\scripts\audit_patent_draft.py" "申请文件.md"
```

从当前 skill 的 `SKILL.md` 所在目录解析脚本路径，不从专利项目目录猜测相对路径。转换文件只用于复核，放入项目过程目录或系统临时目录，不覆盖原 DOCX。

格式脚本只检查能够确定的形式问题：

- 说明书必要章节是否存在；
- 权利要求书和说明书摘要是否作为申请文件组成部分存在；
- 权利要求编号是否连续；
- 权利要求引用是否存在以及是否引用自身或在后的权利要求；
- 每项权利要求是否仅在结尾使用一个句号。

模糊用语、实质重复、参数合理性、单位一致性、内部材料混入、说明书支持、权利要求清楚简要及其他内容问题均由模型全文判断，不由脚本作硬性结论。

脚本报告不是法律或技术结论，不得据此省略模型阅读。

## 第二层：模型全文阅读

模型必须重新阅读说明书、权利要求书、摘要、附图说明和相关内部记录，不能只阅读脚本报告。完成下列全部复核。

## 指令与规范

- 以用户明确命令、已确认技术方案和保护重点为撰写依据。
- 按适用的《中华人民共和国专利法》《专利法实施细则》《专利审查指南》及已经生效的修改决定进行规范化复核。
- 2026 年及以后复核时，将 2023 年《专利审查指南》与国家知识产权局第 84 号令等后续生效修改结合使用。
- 用户要求与通常审查建议存在风险时，提示风险，但不静默改变已经确认的技术方向。

## 文件构成

确认正式申请文件与工作材料分离：

- 说明书；
- 权利要求书；
- 说明书摘要；
- 必要的说明书附图和摘要附图；
- 撰写分析、确认记录和内部《编制数据说明》不得混入正式申请文件。

## 全文一致性

检查：

- 发明名称在各文件中一致；
- 同一技术对象、部件、步骤和参数使用同一名称；
- 附图标号及部件名称一致；
- 参数范围、端点、单位、有效数字和优选范围一致；
- 实施例、对比例、实验例、结果分析和摘要中的数据一致；
- 技术问题、技术手段和技术效果逐项对应；
- 无前后矛盾、无未定义缩写、无突然出现的技术特征。
- 发生确认后变更时，变更影响矩阵覆盖全部受影响文件且已完成同步。

## 说明书

- 技术领域准确；
- 背景技术客观并能引出技术问题；
- 发明内容包含完整技术方案；
- 有益效果能够从技术特征、机理或数据得到；
- 具体实施方式足以使本领域技术人员实现；
- 实施例支持权利要求概括范围；
- 对比例能够隔离核心变量并说明创新特征的重要性；
- 实验例的指标、方法、数据和结论闭合；
- 附图说明与具体实施方式对应。

## 权利要求

- 独立权利要求包含全部必要技术特征；
- 权利要求得到说明书支持；
- 保护范围清楚；
- 每项及整套权利要求简要；
- 无实质重复的同类权利要求；
- 从属权利要求增加真实限定；
- 引用关系和主题名称正确；
- 术语与说明书一致；
- 不含不必要原因、解释、宣传或纯效果表述；
- 不存在明显的单一性、客体或修改超范围问题。

## 数据文件

使用编制数据时检查：

- 已生成独立的内部《编制数据说明》；
- 内部说明覆盖全部编制数据；
- 内部说明与正式申请文件的数据逐项一致；
- 正式申请文件不含内部来源说明；
- 未编造检测报告编号、原始仪器记录或第三方证明。

## 复核输出

输出：

1. 脚本检查结果及已处理问题；
2. 模型全文阅读结论；
3. 已修复问题；
4. 仍需用户决定的问题；
5. 说明书—权利要求支持矩阵结论；
6. 数据一致性结论；
7. 文件构成结论；
8. 提交前需核验的申请人、发明人、权属、优先权、公开情况和附图事项。
