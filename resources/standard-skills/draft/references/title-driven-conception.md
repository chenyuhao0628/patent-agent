# 名称驱动构思

当用户只提供发明名称或一句简短设想时，使用本模块。

## 构思步骤

1. 从名称识别可能的技术领域、应用对象、使用环境和技术目标。
2. 推测该领域中常见但具体的技术问题，避免只写商业目标或抽象效果。
3. 默认围绕不同技术路径构思 3 个可实施方向；确有更多显著不同路径时扩展至 4～5 个。合理方向不足 3 个时说明原因，不为凑数生成薄弱或重复方向。
4. 为每个方向补全能够形成完整技术方案的结构、步骤、参数、控制关系或材料组合。
5. 判断多个方向是否能够围绕一个总的发明构思组合；不能组合时保持为独立候选。

## 每个方向的介绍顺序

- 方向名称；
- 适用场景；
- 需要解决的技术问题；
- 总体技术思路；
- 核心结构、步骤、材料或控制逻辑；
- 拟形成的创新点；
- 预期技术效果；
- 可设置的数据和参数；
- 所需实施例、对比例和实验例；
- 可保护的方法、装置、系统、产品或介质；
- 保护价值、撰写难度和主要风险。

## 推荐与确认

- 先依次完整介绍各方向，再用表格横向比较。
- 方向之间应在核心技术手段上有实质差异；仅改变应用场景、名称或非关键参数不得作为独立方向。
- 从技术完整性、区别特征强度、保护范围、实施可行性、证据需求和后备方案六方面推荐一个主方向。
- 说明推荐理由和次选方向的保留价值。
- 不在用户确认前直接撰写完整说明书。
- 名称可能对应完全不同技术领域时，只询问一个能够区分方向的关键问题；其他缺失内容继续主动构思。
